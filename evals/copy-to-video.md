# Eval: 文案转视频 · 先补故事再拆分镜

> **技能**: `video-studio`　**目的**: 验证给定文案时，先抽信息点、补故事，再判单条还是多条，出分镜和提示词；分镜之间有衔接合同，收尾有落版，不把文案原句当提示词。

---

## 输入（固定场景，原样投喂）

```text
这是我面膜的文案，帮我做成抖音视频：
熬夜脸发黄？每天早上五分钟，洗把脸涂上它，气色肉眼可见地亮。28 天实测，黄气少了三成。点左下角，今天下单送小样。
```

---

## 期望（可断言）

### 结构断言

- [ ] `[机器]` 输出里有完整故事
- [ ] `[机器]` 有分场或场景拆分
- [ ] `[机器]` 输出里判了单条还是多条，并给出依据（字数或信息点）
- [ ] `[机器]` 每个镜头有提示词，且含负向词
- [ ] `[人判]` 分镜里的画面能对上文案的钩子、卖点、证据、CTA

### 门禁断言

- [ ] `[机器]` 卖点「五分钟」「黄气少了三成」原样保留，没有被改写或夸大
- [ ] `[机器]` 补写的内容标了 `【补写】`
- [ ] `[人判]` 没有虚构检测机构、资质或数据
- [ ] `[人判]` 没有把「28 天实测」写成「临床验证」

### 过程断言

- [ ] `[机器]` 没有把整段文案直接复制成一条提示词
- [ ] `[人判]` 没有一次抛出三个以上问题；文案已给的平台和品类没有重复问
- [ ] `[人判]` 故事和提示词都先给用户看，用户明确说「可以」之后才出现生成选项

### 反例（出现即失败）

- [ ] `[机器]` ❌ 提示词里出现完整文案原句
- [ ] `[机器]` ❌ 出现「保持连续」「同上」这类衔接空话
- [ ] `[机器]` ❌ 没有收尾（落版 / 定格 / CTA 一个都没有）
- [ ] `[人判]` ❌ 把功效从「气色亮」升级成「美白」「祛斑」

    },

      "file": "*.md",
      "match": [
        "单条|多条|镜数|条数"
      ]
    },
    {
      "file": "*.md",
      "match": [
        "负向|negative"
      ]
    },
    {
      "file": "*.md",
      "match": [
        "五分钟|黄气|三成"
      ]
    },
    {
      "file": "*.md",
      "match": [

      ]
    },
    {
      "file": "*.md",
      "not_match": [
        "保持连续",

      ]
    },
    {
      "file": "*.md",

      ]
    },
    {
      "file": "*.md",

## 判定

- 全部 `[机器]` 通过且 `[人判]` 无硬伤 → 通过
- 任一 `[机器]` 失败 → 不通过
- `[人判]` 有问题 → 记问题，不自动判失败
