# 技能行为评测（evals）

> 其他检查验的是「结构对不对、引用全不全、触发覆盖够不够」。
> 这里验的是另一件事：**给一个真实输入，技能的产出对不对。**

## 为什么需要

`check-skill.py` 全绿，也可能出问题：招募文案写成卖货腔、秀场话术带施压、零工具场景硬报错、用户说一句它反问三句。

这些只有把真实输入跑一遍才看得出来。

## 评测怎么组织

每条评测一个 `.md`，格式固定：

```markdown
# Eval: <名字>
> **技能**: `/<skill>`　**目的**: <验证什么>

## 输入（固定场景）        ← 原样投喂给技能的一段话
## 期望（可断言）
### 结构断言              ← 每条标 [机器] 或 [人判]
### 门禁断言
### 过程断言
### 反例（出现即失败）
## 机器可判断言（CI 执行）  ← ```json 块，判定器读它
## 判定
```

- **`[机器]`**：判定器自动检查
- **`[人判]`**：人 / 评审子智能体判断，不自动打分
- **过程断言**：看会话记录；没采集时记「未采集」，不算失败

## 机器可判断言能写什么

| 判据 | 语义 |
|---|---|
| `exists` | 文件（支持 glob）至少匹配到 1 个 |
| `sections` | 每个关键词都要出现在某个**标题行** |
| `match` | 每个正则至少命中 1 次 |
| `not_match` | 任一正则命中即失败（禁语 / 反例） |
| `if_match` + `then_match` | 条件断言：命中 A 就必须也有 B |
| `min_count` | `{pattern, min}`：命中次数不得少于 min |
| `optional` | `true` 时文件不存在就跳过 |

## 怎么跑

**第 1 步：把技能真的跑一遍**（这一步要宿主 / 人或子智能体，仓库里跑不了）

把评测的「输入」原样投喂给对应技能，产物拷到：

```text
evals/runs/<评测文件名去掉 .md>/
```

例如 `evals/copy-recruit.md` 的产物放进 `evals/runs/copy-recruit/`。

**第 2 步：判卷**

```bash
python3 scripts/run-evals.py --all      # 判全部（没产物的记「未跑」）
python3 scripts/check-evals.py          # 只验评测定义本身是否完整
```

## 铁律

1. 没跑过就没有产物 → 记「未跑」，**不算失败**。CI 不会因此变红。
2. 期望要写「怎么算对」，不能只写「写得好」。
3. 反例必须写，而且要写具体——「❌ 出现『下单』」比「❌ 不要跑题」有用。
4. 评测定义了就要能跑通判定器，跑不通说明断言写错了，不是技能错了。
