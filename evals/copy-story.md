# Eval: 故事型招人文案 · 讲故事，不讲道理

> **技能**: `copy-video-studio`　**目的**: 验证默认产出是「故事」而不是「道理」——有一个具体的人在经历具体的事，有困难、有转折、有邀请；读者代入的是人，不是行业。

---

## 输入（固定场景，原样投喂）

```text
帮我写条招主播的文案，抖音，给来深圳找不到工作的年轻女孩看
```

---

## 期望（可断言）

### 结构断言

- [ ] `[机器]` 有一个具体的主角（我 / 她 / 我一个朋友）
- [ ] `[机器]` 有具体处境（出租房 / 投简历 / 刷手机这类场景）
- [ ] `[机器]` 有困难或卡点（没人看 / 被拒 / 熬）
- [ ] `[机器]` 有邀请（评论区 / 私信）
- [ ] `[人判]` 六段骨架能对上：处境 → 卡住 → 怀疑 → 看见别人 → 试了 → 邀请

### 门禁断言

- [ ] `[机器]` 没有「月入」「包吃住」「加微信」
- [ ] `[人判]` 没有通篇讲道理（不是「因为……所以……」的议论文）
- [ ] `[人判]` 没有把困难删掉，只讲好
- [ ] `[人判]` 结果没有编造具体收入数字

### 过程断言

- [ ] `[机器]` 没有一次抛出三个以上问题
- [ ] `[人判]` 没有先问一堆再动笔

### 反例（出现即失败）

- [ ] `[机器]` ❌ 出现「月入」「包吃住」
- [ ] `[人判]` ❌ 通篇是「行业前景好」「赛道选择」这类议论
- [ ] `[人判]` ❌ 主角是「你」，全篇在教训读者
- [ ] `[人判]` ❌ 编造「月入五万」这类结果

---

## 机器可判断言（CI 执行）

```json
{
  "checks": [
    {"file": "*.md", "match": ["我|她|朋友"]},
    {"file": "*.md", "match": ["出租房|投简历|刷手机|躺着|上班"]},
    {"file": "*.md", "match": ["没人看|不合适|难|熬|干"]},
    {"file": "*.md", "match": ["评论区|私信"]},
    {"file": "*.md", "not_match": ["月入", "包吃住", "加微信"]}
  ]
}
```

## 判定

- 全部 `[机器]` 通过且 `[人判]` 无硬伤 → 通过
- 任一 `[机器]` 失败 → 不通过
- `[人判]` 有问题 → 记问题，不自动判失败
