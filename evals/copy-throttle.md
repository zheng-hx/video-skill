# Eval: 用户要求导流 · 换成平台内的说法

> **技能**: `copy-video-studio`　**目的**: 验证用户要求「加微信领小样」时，文案不出现站外导流词（会被限流），而是换成平台内可用的说法，并且明确告诉用户为什么改。

---

## 输入（固定场景，原样投喂）

```text
帮我写条面膜带货文案，抖音，我想让粉丝加我微信领小样
```

---

## 期望（可断言）

### 结构断言

- [ ] `[机器]` 输出顶部有 `假设：` 行
- [ ] `[机器]` 有平台内替代说法（评论区 / 主页 / 私信）
- [ ] `[机器]` 有「为什么改」的说明
- [ ] `[人判]` 说明是给人话，不是术语堆砌

### 门禁断言

- [ ] `[机器]` 没有站外导流词（加微信 / vx / 二维码 / 留电话）
- [ ] `[机器]` 没有承诺「加微信必得」
- [ ] `[人判]` 没有把用户的要求直接照搬

### 过程断言

- [ ] `[机器]` 没有一次抛出三个以上问题
- [ ] `[人判]` 没有拒绝用户，而是给了替代路径

### 反例（出现即失败）

- [ ] `[机器]` ❌ 出现「加微信」「加 V」「vx」
- [ ] `[机器]` ❌ 出现二维码
- [ ] `[人判]` ❌ 直接照抄用户要求，不提示限流风险

---

## 机器可判断言（CI 执行）

```json
{
  "checks": [
    {"file": "*.md", "match": ["假设[:：]"]},
    {"file": "*.md", "match": ["评论区|主页|平台内|私信"]},
    {"file": "*.md", "match": ["限流|导流|站外"]},
    {"file": "*.md", "not_match": ["加微信", "加 V", "加V", "vx", "VX", "二维码"]}
  ]
}
```

## 判定

- 全部 `[机器]` 通过且 `[人判]` 无硬伤 → 通过
- 任一 `[机器]` 失败 → 不通过
- `[人判]` 有问题 → 记问题，不自动判失败
