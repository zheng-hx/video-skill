# 记忆机制

> 目标：用户第二次只说「再来一条」，你也能出对东西。
> 这里的每一条都是为了让用户少说一遍。

## 档案存在哪（按优先级找）

1. `~/.copy-video-studio/profile.md` —— **首选**，跨项目可用
   - 没有就建：`mkdir -p ~/.copy-video-studio`，再把 `assets/profile-template.md` 复制成 `profile.md`
2. 当前项目根目录的 `profile.md` —— 上一条写不了时用
3. 都没有 → 直接用默认值生成，结尾问一句「要不要我记住这些设定」

> 三种位置都只读不写不了时，就靠对话上下文；同时在回复末尾附一小段「本次设定」，方便用户下次粘贴。

## 档案里记什么

见 `assets/profile-template.md`。核心是四块：

| 块 | 记什么 | 谁在用 |
|---|---|---|
| 业务 | 品牌、品类、客单价、目标人群 | 定卖点和人群 |
| 内容偏好 | 常用平台、时长、调性、喜欢的/讨厌的表达 | 定写法 |
| 合规雷区 | 禁用词、不能碰的功效 | 定边界 |
| 历史产出 | 日期、类型、平台、结果 | 找规律 |

## 三条推断规则（按顺序，别跳）

### 1. 单点变更

用户只说了变化的那个维度，其他一律沿用上次。

```
上次：面膜 + 小红书 + 种草体 + 温和调性
这次：用户说「换抖音」
→ 面膜 + 抖音 + 种草体 + 温和调性（后两个不变）
```

### 2. 隐含复用

用户只说「再来一条」「换个角度」「写第二个」，等于「其他都不变，重写一版」。

- 「再来一条」→ 同设定，换角度
- 「换个开头」→ 只改钩子，其余保留
- 「短一点」→ 同设定，压时长

### 3. 固化

用户说「以后都按这个来」「我们一直做这个平台」→ 写进 profile，并标注为默认。

## 什么时候更新档案

| 触发 | 动作 |
|---|---|
| 用户给了新信息（品类、平台、人群） | 写入对应字段 |
| 用户明确否定某个写法 | 记进「讨厌的表达」 |
| 用户说「以后都这样」 | 写入并标记默认 |
| 产出了一条用户明确满意的 | 记进历史产出，标注「满意」 |

**不要**把每次生成的内容都塞进档案。档案只存**跨次复用**的信息，不是日志。

## 冲突了怎么办

- 用户这次说的，**永远覆盖**档案里的旧值。
- 覆盖时更新「来源」和「更新于」两列，不要直接抹掉历史含义。
- 如果用户说的和档案矛盾但没说改，**按用户这次的来**，并在假设行里点一句「按你这次的设定，档案里那版先不动」。

## 别做的三件事

1. 不要问已经被记录过的事。先查档案，再决定问不问。
2. 不要因为档案存在就拒绝用户的新方向。档案是默认值，不是牢笼。
3. 不要把档案写成一堆流水账。字段就那几个，多了反而没人看。
