# 规则自动刷新

> 合规清单会过期。平台规则变了，旧清单就成了「照着做也挨罚」的陷阱。
> 这里规定：什么时候刷新、从哪刷、刷完怎么存。

## 1. 什么时候刷新

| 触发 | 动作 |
|---|---|
| 快照超过 **7 天** | 生成文案前自动刷一遍 |
| 用户说「最近管得严」「又被限流了」 | 立刻刷 |
| 用户要发的类目第一次出现（比如第一次写医疗） | 刷一次该类目 |
| 平台发公告（用户转给我们） | 记为规则变更，标 stale |

**不刷新就生成**，等于拿旧地图找路。

## 2. 从哪儿刷（可信度从高到低）

| 来源 | 地址 | 抓得到吗 |
|---|---|---|
| 抖音社区自律公约 | `https://www.douyin.com/rule/policy` | 页面是 SPA，正文抓不到，只能拿标题 |
| 星图规则中心（创作者违规管理规则） | `https://www.xingtu.cn/help-center/author/140379` | ✅ 能抓全文 |
| 抖音安全中心公告 | `https://www.douyin.com/security` | 待验证 |
| 巨量学 / 电商规则 | `https://school.jinritemai.com` | 待验证 |
| 搜索「抖音 违规 新规 2026」 | web_search | ✅ 能拿到二手信息 |
| 蝉妈妈 / 新榜等三方 | — | 参考，不当依据 |

**官方 > 三方 > 社区经验**。三方说的要标注「未证实」。

## 3. 刷新流程

1. 先看快照日期，过期才刷。
2. `web_search` 搜「抖音 违规 新规 <当前年月>」「抖音 限流 新规」。
3. 对官方页面 `web_fetch`，抓正文。
4. 提炼：**新增/收紧**了什么，删了什么，处罚升级了吗。
5. 写进 `assets/rules-snapshot.md` 的快照文件，标日期和来源。
6. 对比旧快照，**有变化就告诉用户**：「平台最近收紧了 X，你之前的写法要换。」

## 4. 快照存哪

```text
~/.video-design/rules/
├── 2026-11-09-抖音.md     # 当天快照
└── latest.md              # 指向最新（软链或复制）
```

快照格式见 `assets/rules-snapshot.md`。

## 5. 快照里必须有什么

- 抓取日期和来源 URL
- 这次相比上次**变了什么**（新增红线 / 放宽 / 处罚升级）
- 当前生效的红线词和限流词（能直接给 `check-copy.py` 用）
- 对文案的影响：哪些写法要换

## 6. 诚实边界

- **平台不会公开所有限流规则**，很多是审核黑盒，同一条文案不同账号结果不同。
- 搜到的三方「违禁词大全」经常过时或瞎编，只能当线索，不能当依据。
- 快照能降低踩线概率，**不能保证**不被限流。
- 用户被告知限流时，第一动作是**记规则变更 + 标 stale**，不是改词重发。

## 7. 自检

- [ ] 快照日期在 7 天内
- [ ] 来源标了 URL
- [ ] 写清了「比上次变了什么」
- [ ] 新红线已经同步给 `check-copy.py` 的词表
- [ ] 有变化时告诉了用户
