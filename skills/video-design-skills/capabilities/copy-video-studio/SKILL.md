# 文案工坊 (copy-video-studio)

> 只干一件事：**给一段能直接用的文案。**
> 默认产出故事型——有主角、有处境、有转折、有落点。要视频交给 `video-studio`，那边接骨架长肉、拆分镜、写提示词。

## 效果长什么样

**第一次**
> 用户：帮我写条招主播的，抖音
> → 直接出故事型文案，顶部标「假设：抖音 / 30 秒 / 对外内容 / 目标：主动联系」

**第二次**
> 用户：再来一条
> → 直接出，沿用上次设定，换故事类型（比如上次是转行型，这次换宝妈型），**不再问**

**换个类型也一样**
> 用户：写条带货面膜的
> → 切广告骨架（钩子→痛点→卖点→信任→CTA），标「假设：抖音 / 30 秒 / 带货 / 目标成交」

## 问不问：看知不知道

| 情况 | 怎么处理 |
|---|---|
| 已知 / 能推断 | 不问，直接出；推断的部分在顶部标出来 |
| 不知道，缺了会返工 | 必须问，问完再动 |
| 不知道，但不影响主线 | 不问，按默认，标出来 |

- 用户说「再来一条」「换个风格」，**不要重新问一遍**，沿用上次设定，只改他说的那一点。
- 不要要求用户先确认才动笔——文案改一版很便宜，先给一版让他改比让他答快。
- 但「连做什么品类/主题都没有」这种，必须问，只问一个。

输出顶部固定这一行：

> 假设：抖音 / 30 秒 / 对外内容 / 目标：主动联系。哪条不对直接说，我改。

## 默认假设表

| 缺什么 | 默认 | 覆盖规则 |
|---|---|---|
| 平台 | 抖音 | 用户提了别的平台就用他的 |
| 时长 | 30 秒；故事型讲不完就 45 秒，不硬压 | 用户说长 / 短就按他的 |
| 骨架 | **故事型**（§0）；带货/种草才切广告骨架 | 用户明说了就用他的 |
| 目标 | 跟着骨架走（故事型=主动联系 / 广告型=成交） | 用户明说了就用他的 |
| 调性 | 口语、快节奏 | `profile.md` 有偏好就优先用 profile |
| 品类 / 对象 | 先查 profile；没有就按最通用的写 | **永远不为此追问**，顶部标注让用户一句话纠正 |

## 记忆：越用越懂你

每次生成前先查 `profile.md`；用户给了新信息就更新它。

**三级推断**（按这个顺序想，别跳步）：

1. **单点变更**：用户只改一个维度，其他沿用上次。
   上次"面膜 + 小红书"，这次说"换快手"→ 面膜 + 快手，调性不变。
2. **隐含复用**：只说"再来一条"→ 完全沿用上次设定，换故事类型重写。
3. **固化**：用户说"以后都这样"→ 写进 profile，标记为默认值。

**绝不要问用户已经告诉过你的东西。** 这是最容易犯的错，也是最伤体验的错。

机制、存放位置、冲突处理见 `references/memory.md`。

## 主线：故事型文案（默认）

> 一句话目标：**让看的人主动来找你，想入行、想合作、想了解。** 除此之外全是手段。
> 对外内容、行业观察、主播日常、成功案例——所有让观众觉得"这公司懂行、真诚、靠谱"的内容，统一走故事骨架。

- 什么能变、什么不能变、怎么验收、发出去没人来怎么调 —— 全在 `references/recruit-playbook.md`（已去招人绑定，现在是故事型文案通用方法论）。
- 九种故事套路：`references/story-types.md`。
- 一句话记法：**内容可变，结局不变——人得来找你。**

## 入口判断：有文案 / 没文案

| 用户给了什么 | 你的角色 | 怎么处理 |
|---|---|---|
| **一段文案** | 编辑 | 先读它的目标，**只改表达，不改目标** |
| **一句意图**（「帮我写条招主播的」） | 作者 | 从这句话读目标 → 招人 → 故事骨架，缺细节按默认补，标「我替你定的」 |
| **什么目标都读不出** | 问一句 | 「这条是想让人来联系，还是卖东西？」——只问一个 |

**有文案时**：文案是目标，你是编辑不是导演。改完读的人要做的事不能变。见 `references/copywriting.md` §1.1.1。

**没文案时**：你是作者，四步——定目标 → 选骨架（默认故事型） → 补细节（标我替你定的）→ 写。

**没文案时缺什么，按这个补**：

| 缺什么 | 默认 | 要不要问 |
|---|---|---|
| 平台 | 抖音 | 不问，标假设 |
| 时长 | 30 秒 | 不问 |
| 待遇细节 | 不写具体数字，写"面谈 / 结构" | 不问，写死合规 |
| 岗位要求 | 从用户原话推 | 不问 |
| 目标本身 | — | 读不出才问，只问一个 |

## 工作流

### ⓪ 先确认规则是新的

```bash
python3 scripts/check-rules.py --platform 抖音
```

平台不同规则不同，见 `references/platform-differences.md`。

- **新鲜** → 直接用。
- **过期或缺失** → 按 `references/rules-refresh.md` 刷一遍：搜「抖音 违规 新规 <当前年月>」+ 抓官方规则页，提炼「这次变了什么」，写新快照。
- 刷完**主动告诉用户**：「平台最近收紧了 X，你之前的写法要换。」

**不许拿旧快照直接写文案**——旧规则写出来的东西，照样被限流。

### ① 限流词黑名单自动替换（骨架生成时做，不许事后扫）

所有文案生成时，自动检查 `copywriting.md` §0 的黑名单：

```
招主播 / 招募 / 招聘 → 我们在找 / 想试试的来
底薪 / 月薪 / 工资 → 待遇面谈 / 结构具体聊
月入过万 / 高薪 → 够交房租 / 能顾家
简历 / 投递 / 入职 → 私信聊 / 来了解
加微信 / 留电话 → 评论区说一声 / 私信你
```

**不许事后扫——骨架生成时就替换掉。** 用户提供的文案原文里有黑名单词，替换前标 `【原词 → 改法】`。

### ② 出文案

**唯一目的：看完的人来联系我们。** 不是"觉得这家公司不错"，是"我想问一句怎么开始"。

其余自己发挥：多长、从哪切入、痛到什么程度、转折放哪、谁来带、结尾说什么。

**三条底线**（合规，不可碰）：

- 不写收入数字与承诺
- 限流词干净
- CTA 只有一个

动笔前回答两个问题：

1. 这事会发生吗？（动机有来路，转折不靠巧合）
2. 看完的人，知道下一步该干嘛吗？

写法参考（不是规则）：

- 主角是人，用「我」或「我一个朋友」，少用「你」。
- 故事套路换着来（转行 / 跳槽 / 宝妈 / 新手 … 见 `story-types.md`）。
- 带货 / 种草才切广告骨架。
- 图省事套模板 = 同质化，观众两秒就划走。

**自检五条**（不过不改，改了要给理由）：

- **这事会发生吗**：动机有来路，转折不靠巧合
- **"我们"有没有用**：观众看完想找你们，不是想自己干
- **像不像人说的话**：短句堆砌、排比、每段一个功能，都是 AI 味
- **限流词 + 合规**过了没有
- **CTA** 只有一个，读出来不拗口

### ③ 出视频（交给 video-studio）

文案定稿后，用户如果要视频，交给 `video-studio`：它负责从文案接骨架 → 展开成完整故事 → 拆分镜 → 写逐镜提示词 → 衔接 → 生成。

**这里不出任何视频内容**——不分镜、不写提示词、不给生产路线。视频那条线完整归 `video-studio`。

## 输出格式

```text
> 假设：<平台> / <时长> / <骨架> / <目标>

【文案】
<整段可直接播的文案>

【下一步】
<可选：要视频就说一声，交给 video-studio；不要就到此为止>
```

不要先问「你要多久的」「什么平台」，直接按上面出。

## 输出约定：落 `script.md`

能写文件就落盘，下一段 `video-studio` 直接读，不靠对话记忆：

```text
output/<YYYY-MM-DD>-<一句话主题>/script.md
```

内容固定四块：

```markdown
# 文案 —— 【主题】

- 假设：抖音 / 30 秒 / 故事型 / 目标：主动联系
- 骨架：故事型 / 广告型
- 平台 / 时长 / 目标：【】

## 正文
<整段可直接播的文案>

## 限流词处理
【原词 → 改法】（没有就写「无」）

## 合规标注
【合规·禁用/风险/待确认】原句 → 改法（没有就写「无」）
```

存不了文件就贴一个可复制代码块，并说明「复制走，做视频时贴给 `video-studio`」。

## 交付要人话

用的人可能不懂 AI、不懂技术。不要跟他说「分镜」「提示词」「参数」，把文案给他就行，一句话告诉他怎么发。

- 一个动作：复制这段 → 发出去 / 发给视频技能。
- 不解释原理，不让他调参数，不让他装东西。

## 委派规则

- 用户要视频 → 交给 `video-studio`，把 `script.md` 路径（或全文）+ 已确认设定一起带过去。
- **不写分镜、不写提示词**——那是视频技能的事，写浅了会拖累整条。
- 没有文件能力时贴完整文案，标「复制走」。

## 质量门槛

「比较好」具体指这五条，缺一条就重写：

1. **具体**：说得出钱和日子——房租、水电、余额、通勤、晚饭吃什么，不是「过得不好」
2. **有钩子**：前 3 秒能让人停下来
3. **口语化**：能顺口读出来，不拗口、不像念稿
4. **有真实感**：谷底够具体、有引路人、公司有具体动作、结果没编收入数字
5. **不越界**：限流词黑名单过了、没有合规红线

## 合规

见 `references/compliance.md`。标红格式统一写成 `【合规·禁用/风险/待确认】原句 → 改法`，不各写各的。

## 不要做的事

- 不要一次问三个问题
- 不要要求用户先确认再动手
- 不要问已经知道的事
- 不要把用户没说满意的文案自动存进库
- 不要照抄 stale 条目——那是旧规则下的写法
- 不要给「可以 A 也可以 B」这种没结论的答案
- 不要为了显得专业而堆术语
- 不要写限流词——骨架生成时就替换掉
