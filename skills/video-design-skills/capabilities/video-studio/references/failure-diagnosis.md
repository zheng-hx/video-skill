# 失败诊断与重跑

> 生成出来不对，先别急着重跑。**先定位是哪一段的问题**，改完再跑。
> 乱重试是浪费额度：同一个提示词跑十次还是那个毛病。

## 1. 先分清三类失败

| 类型 | 表现 | 怎么处理 |
|---|---|---|
| **门禁失败** | `check-storyboard.py` 报 FAIL | 按报错改字段，改完重跑门禁 |
| **生成失败** | 门禁过了，画面不对 | 按下面的现象表诊断 |
| **交接失败** | 下游说缺东西 / 重问已知 | 补交接物，见 `references/workflow-protocol.md` |

## 2. 现象 → 根因 → 改哪 → 重跑哪段

| 现象 | 根因 | 改哪里 | 重跑 |
|---|---|---|---|
| 角色每镜换脸 | 没引用角色 id，或没参考图 | 角色卡 + 每镜 `character_refs` | 生成 |
| 色调一镜一个样 | 风格锚被改写、缺失 | `style_anchor` 逐字统一 | 生成 |
| 相邻镜头跳 | handoff 没写或写成空话 | `end_state` / `next_start_state` 写可见事实 | 生成 |
| 一条里动作只做一半 | 一条塞了 >2 个主动作 | 拆镜 | 分镜 → 生成 |
| 人物左右互换 | 没写站位和朝向 | `layout` 描述、handoff 的 `match_on` | 生成 |
| 字幕和口播对不上 | 时长预算算错 | 重算时长，改 `meta.duration` | 分镜 → 生成 |
| 画面很平 | 光线没写方向 | 光线字段：源 + 向 + 强度 + 色温 | 生成 |
| 出现文字 / 水印 | 负向词缺 | `negative` 补上 | 生成 |
| 手畸形、脸崩 | 约束层缺 | 补「结构正常、五官稳定」 | 生成 |
| 风格串台 | 平台语法错配 | 按 `prompt-templates.md` 的平台语法表改写法 | 分镜 |
| 故事对不上卖点 | 故事改过头 | 改 `story.md`，对照原文 | 故事 → 分镜 |
| 结尾戛然而止 | 没有 `ending` | 补收尾，停留 ≥1.5 秒 | 分镜 → 生成 |

## 3. 重跑四条规矩

1. **只重跑出问题那一段**，不回退已通过的段。
2. **先改再跑**：每次重跑必须对应一处具体修改，不裸跑。
3. **同问题最多重试 2 次**：还不行就换策略——换平台、换风格、拆镜、降级成制作包。
4. **每次记一笔**：改了什么、跑了几次、结果变了什么。同一段第三次还不过，就停下来报告，别烧额度。

## 4. 重跑前自检

- [ ] 定位到了具体镜头 / 具体字段，不是「整体重写」
- [ ] 改动能对上现象（不是瞎改）
- [ ] 已知的设定没被顺手改掉
- [ ] 这次重跑有明确目的

## 5. 自动编排契约（宿主有 workflow 能力时）

技能包本身跑不了自动重试。但如果宿主支持编排，可以按这个契约实现：

```text
输入：story.md
循环（最多 2 轮）：
  1. 生成 storyboard.json
  2. 跑 check-storyboard.py
  3. 失败 → 读「门禁失败」→ 改字段 → 回到 2
  4. 通过 → 交给用户生成
  5. 用户报画面问题 → 读第 2 节现象表 → 改对应字段 → 回 1
输出：storyboard.json + 修改记录 + 未解决项
```

约束：

- 每轮必须记录「改了什么」，不能静默重试。
- 2 轮还不行，必须停下来把未解决的项列出来，交给人。
- 不许为了让门禁变绿而改掉卖点、价格、CTA。

## 6. 什么时候不该重跑

- 根因是**故事错了**——重跑一百次也没用，回去改 `story.md`。
- 根因是**平台不支持**——比如要精准对口型但手头只有不对口型的工具，换平台或降级，别硬跑。
- 根因是**用户没确认的关键项**——回去问，别自己猜。
