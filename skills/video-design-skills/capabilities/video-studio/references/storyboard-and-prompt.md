# 分镜与提示词

> 上游是 `story.md` 里的**完整故事和分场**，不是对话记忆，也不是一句话索引。

## 0. 先定风格（会改掉后面所有写法）

风格不是「加个形容词」，是换一套写法。同一个故事，真人写法和漫剧写法完全不同。

| 风格 | 适合 | 风格锚示例 | 关键要求 |
|---|---|---|---|
| **真人实拍感** | 带货 / 口播 / 人设 / 故事型 | 暖调、浅景深、手持微晃、低饱和、真实生活感 | 皮肤质感自然，光线可信，口型要对 |
| **AI 漫剧** | 剧情 / 短剧 / 知识 / 情感 | 日系赛璐璐动画风、平涂、清晰描边、高饱和、无真实噪点 | 角色三视图锁死，表情夸张，口型可不对 |
| **3D 动画** | 科普 / 儿童 / 产品演示 | 3D 渲染、柔光、圆润造型、干净背景 | 材质要写清，布光要写清 |
| **插画 / 图文** | 种草 / 知识 / 清单 | 扁平插画、莫兰迪色、纸质感、无阴影 | 平面构图，文字排版留位 |
| **混合** | 口播 + 素材包装 | 真人主体 + 图文包装层 | 层级分明，主体不被包装抢 |

### 混搭不是随便混

`mixed` 要写清三件事：**两个世界各是什么、交界在哪、谁在谁里**。

### 怎么选

1. 用户明说了风格 → 按他的。
2. 没说 → 按类型推荐：带货/口播 → 真人；故事/情感 → 漫剧或真人；科普 → 3D 或图文。
3. 推荐时给两个选项，别只给一个：「这条我建议真人实拍，也可以做成 AI 漫剧，你选哪个？」——**这是会返工的项，必须确认。**

**选完风格，下面写角色卡和 negative 词都要跟着变**。别选完风格就忘了这步，那就是白选。

## 1. 角色卡：先定人，再定图

角色卡分三层：**身份锚点**（年龄+脸型+发型走向+发色+标志性特征）、**造型**（款式+颜色+质感+发型状态）、**设计意图**（为什么长这样）。缺一层，模型就会画成路人甲。

**角色卡定完，必须先出参考图（Step 0.0，强制）**——靠文字描述脸，模型每次画都不一样；先出一张照片级人物参考图，视频用图生视频，一致性直接锁死。

> 参考图预生成流程、提示词模板、各平台引用语法、多镜头收束 → `pre-production.md` §2

## 2. 判单条还是多条（**先判，判了就别改**）

### 核心原则：**按情绪/节奏阶段拆，不是按字数/时长硬算**

我之前写的"主动作>2才拆"是懒办法。真正决定拆不拆的是：

> **这条故事里有几个独立的情绪/信息阶段？每个阶段模型能在 15 秒内精确出吗？**

| 故事结构 | 建议 | 为什么 |
|---|---|---|
| 情绪弧线简单（起→承→落），全在同一场景 | 一条就行，用时间轴分段 | 模型一次能处理 |
| 情绪有 3+ 个独立阶段（温柔→严肃→温暖→神秘） | 拆成多段 | 模型一次处理不了 5 种表情变化，拆开每段情绪集中，表情精确 |
| 场景确实要换（比如从出租屋到面试现场，是故事本身的需要） | 拆 | 换场景必须拆 |
| 有对比画面（前后对比、多人对比） | 拆 | 对比必须两个画面 |
| 主角有「说给镜头听」+「画面展示」两种模式交替 | 拆 | 口播镜头和展示镜头是两种不同的模型模式 |

### ⚠️ 场景约束：**能不换就不换**

"换场景就拆"是**迫不得已才触发**的规则，不是"可以换就换"。同一场景演完起承转合（见 `story-from-copy.md` §A.2）是默认——环境越稳定，人物变化越突出，承接越顺，token 还省。

只有在"故事本身确实需要换场景"（比如投简历必须去公司、转机发生在地铁上捡到一张卡）才允许换。**不要为了让视频"丰富"就换场景。**

### 那个五段例子为什么拆得对

| 段 | 情绪阶段 | 模型能精确出吗 |
|---|---|---|
| s1 | 温柔回忆 + 看手机 | 能，一个情绪 |
| s2 | 认真解释 + 手势 | 能，一个情绪 |
| s3 | 皱眉严肃 + 劝退 | 能，一个情绪 |
| s4 | 温暖微笑 + 希望 | 能，一个情绪 |
| s5 | 凑近神秘笑 + 邀请 | 能，一个情绪 |

如果硬塞一条，模型要在 15 秒里出 5 种不同表情变化——大概率只出前两种。拆开每段 8-10 秒，每段一个情绪阶段，表情能精确到位。

**所以那种拆法是对的，"单条优先"是错的。**

### 字数/时长判据是**辅助**，不是主判

```text
推荐条数 = max( 情绪阶段数, ceil(总时长 ÷ 单次上限), ceil(口播字数 ÷ (单次上限 × 4.5)) )
```

取三个里最大的那个。**情绪阶段数优先**，时长和字数只是兜底。

### 必须告诉用户"为什么拆/为什么不拆"

每判一次必须说清楚**按什么判据**：

| 决策 | 告诉用户什么 |
|---|---|
| 判单条 | "这条情绪阶段不多，**一条就能出**，15 秒装得下所有内容" |
| 判多条 | "这条有 **N 个独立情绪阶段**（[具体列出：温柔→严肃→温暖→神秘]），一条塞不进去，拆成 K 段每段情绪集中，表情能精确到位。" |

### 各平台单次上限（以实际为准）

| 平台单次上限 | 情绪阶段建议 | 动作数建议 |
|---|---|---|
| 5 秒 | ≤ 1 | ≤ 1 |
| 10 秒 | ≤ 2 | ≤ 2 |
| 15 秒 | ≤ 2-3 | ≤ 2 |

## 3. 拆段时的视觉补写：**把抽象文字变成画面（补写方式取决于风格）**

文案里的抽象表达，视频里必须变成**看得见的画面**——但补写方式不能乱：

| 补写方式 | 适合风格 | 不适合风格 | 示例 |
|---|---|---|---|
| 背景叠半透明剪影 | AI 漫剧 | 真人实拍（真人实拍叠剪影像特效） | "她当年也是" → 背景叠半透明（当年的她镜前练习） |
| 漂浮插画/元素 | AI 漫剧、混合 | 纯真人实拍 | "给普通女孩一条出路" → 漂浮笑脸插画 |
| 字幕卡飘文字 | 所有风格 | — | "余额 127.6" → 特写飘字幕 |
| 道具变化 | 真人实拍、AI 漫剧 | — | "时间流逝" → 外卖盒堆了/窗帘拉上了/桌上多了东西 |
| 手机屏幕内容变化 | 所有风格 | — | "没人看" → 手机屏幕显示"观众：0" |
| 同一手/同一脸的对比 | 所有风格 | — | "之前揉简历现在举手机笑" |

**核心**：真人实拍用道具变化+字幕卡；AI 漫剧可以加背景叠层和漂浮元素。别在真人实拍里用漫剧的补写方式。

## 4. negative 词：**针对风格精准拦，别写模糊词**

### 为什么

negative 写模糊了等于没写。「不要 AI 感」这种话模型看不懂——你要的就是 AI 生成的，什么叫"不要 AI 感"？模型会理解成"不要真实照片感"，但你要的可能是真人实拍感。

### 正确写法：风格决定 negative

| 你要的风格 | 应该拦什么（精准） | 别写什么（模糊） |
|---|---|---|
| **AI 漫剧** | 真实照片感、真实皮肤纹理、3D渲染、3D材质、立体光影 | 不要 AI 感、不要真实感 |
| **真人实拍感** | 漫画感、手绘感、3D渲染、插画感 | 不要假、不要卡通感 |
| **3D 动画** | 平面插画、漫画线条、真实照片皮肤 | 不要扁平、不要真实 |
| **插画 / 图文** | 真实照片感、3D 立体光影 | 不要 AI 感 |

### 通用红线（所有风格都要拦）

```
水印、字幕、文字、二维码、其他品牌logo、手机号、畸形手、多余人物、面部漂移、塑料感
```

### 每镜的 negative 可以微调

- 最后一镜如果有 CTA 字幕位 → 负向里加"杂乱文字"
- 有背景剪影/插画 → 负向里加"多余清晰人物"（剪影不能变成真人）
- 有特写镜头 → 负向里加"模糊"

> 反向约束怎么写才不被模型忽略（独立成块 + 标题「务必加上」）：见 `pre-production.md` §4。

## 5. handoff 必须写 match_on

### 为什么

handoff 合同里的 `match_on` 是告诉模型"这几个维度必须跟上一段对得上"。不写 match_on，模型每镜都是独立生成，人物换脸、衣服变了、光线跳了都很正常。

### 正确写法

```json
{
  "from": "s1",
  "to": "s2",
  "mode": "continuous",
  "end_state": "阿岚抬头看向镜头，双手自然放在腿上",
  "next_start_state": "阿岚看向镜头，双手轻摊准备说话",
  "match_on": ["wardrobe", "lighting", "gaze"]
}
```

### match_on 可选值

| 值 | 意思 | 什么时候写 |
|---|---|---|
| `wardrobe` | 衣服/造型 | 几乎永远写——衣服不能换 |
| `lighting` | 光线基调 | 几乎永远写——光线不能跳 |
| `gaze` | 视线方向 | 人物在看的方向要连 |
| `hand_position` | 手部位置 | 手上有动作时写 |
| `hair` | 发型 | 发型不能变 |
| `bg_geometry` | 背景布置 | 有背景细节时写 |
| `frame_ref` | 构图参考 | 构图要连 |

### 原则

- **至少写 2 个**（wardrobe + lighting 几乎永远有）
- 有动作时加 hand_position
- 有视线变化时加 gaze
- 别写太多——3-4 个够了，写 10 个模型也记不住

## 6. 镜头选择：**为情绪服务，不是瞎选景别**

### 镜头和情绪的对应关系

| 情绪 | 适合的景别 | 适合的运镜 |
|---|---|---|
| 温柔、回忆、叙事 | 中景→中近景 | 缓慢推近（慢慢进入） |
| 认真、真诚、解释 | 中近景 | 固定/略推（让人觉得"我在听"） |
| 严肃、劝退、警告 | 近景 | 固定（放大表情） |
| 温暖、希望、开放 | 中景 | 缓慢拉远（让观众看到更大画面） |
| 亲密、神秘、悄悄话 | 近景→特写 | 缓慢推近（凑近镜头） |
| 动作、活力、节奏 | 中景 | 跟随/快速推（有动感） |

### 一个拆得好的例子

| 段 | 情绪 | 镜头 | 为什么是这个 |
|---|---|---|---|
| s1 温柔回忆 | 温和 | 中景推近 | 从远到近，像慢慢进入回忆 |
| s2 认真解释 | 真诚 | 中近景固定略推 | 固定镜头让人觉得"我在听她说话" |
| s3 皱眉劝退 | 严肃 | 近景固定 | 近景放大表情，严肃感出来 |
| s4 温暖微笑 | 希望 | 中景拉远 | 拉远让观众看到背景笑脸环绕的画面 |
| s5 凑近神秘笑 | 亲密 | 近景推到特写 | 凑近镜头就是要制造悄悄话的亲密感 |

### 不许瞎选

- 别写"电影感"——那是风格，不是镜头
- 别写"好看的角度"——模型不知道什么是"好看"
- 别每段都推近——推完推远，镜头有呼吸感

### 拆了之后怎么拆：看平台能力

| 平台 | 有时间轴分段 | 没时间轴分段 |
|---|---|---|
| Seedance / 可灵画映 | 一条里用 `[0-3秒]...[3-6秒]...[6-10秒]...` | 拆成 N 条独立提示词 |
| 即梦（新版） | 部分支持 | 拆成 N 条独立提示词 |
| Veo / Sora | 不支持 | 拆成 N 条独立提示词 |

> 有时间轴的优先用时间轴——一条提示词里控制每几秒做什么，比拆成多条一致性好得多。

## 7. 提示词骨架：全片共享字段 + 每镜独有字段

### ⚠️ 内部矛盾的根因和解法

之前的 14 字段要求**每镜都写满**，但 `continuity-and-handoff.md` 又说"后续镜不再重述外貌"。这两个矛盾导致 Agent 夹在中间：要么字段不全被门禁拦，要么全写上——全写就每段开头都一模一样。

**解法**：把字段分成两层——

| 层 | 包含 | 写法 |
|---|---|---|
| **全片共享字段**（首镜完整写，后续用"全局保持：..."重申） | 风格锚、身份锚点（主体五官长相）、光线基调 | s1 完整写；s2 开头固定一行：**"全局保持：<风格锚>，<身份锚点>，<光线基调>"** |
| **每镜独有字段**（每镜正常写，不许省略） | 造型（可按镜头变）、表情、动作、具体场景细节、构图、镜头（景别+运镜）、质感、约束、负向词、参数、声音 | 每镜各自写 |

### 共享字段清单

| 字段 | 写到什么程度 | 例子 |
|---|---|---|
| **风格锚** | 逐字，全片不变 | 暖调、浅景深、手持微晃、低饱和、真实生活感 |
| **身份锚点** | 主体的**五官长相**，逐字不变 | 28 岁女性，圆脸，内双，齐耳短发，偏白 |
| **光线基调** | 光源+方向+色温 | 左侧窗户进来的阴天自然光，色温偏冷 |

**风格锚别只写"暖调、浅景深"**——要写到摄影设备 + 胶片/镜头 + 调色方向那一级，模板见 `pre-production.md` §3。

**为什么这样分**：风格锚、长相、光线是三个决定"这是同一个人、这是同一个世界"的东西。模型每次独立生成时，必须每次都告诉它这三件事，不然它就重新发明一个新人。但**不能用完整描述**——那样每段开头就长一样。用"全局保持"一行就够。

### 后续镜开头固定格式

```
全局保持：<风格锚>，<身份锚点>，<光线基调>。接上一镜：<上一镜结束状态，是可见事实>，现在<本镜动作，是具体的三段式：起点→过程→终点>。结尾<本镜结束状态>。
```

### 示例（三段提示词，真人实拍感）

```text
===== 第 1 段 · 0-4 秒 · 首镜，完整共享 + 独有 =====

【共享字段（首镜完整写）】
暖调、浅景深、手持微晃、低饱和、真实生活感。
28 岁女性，圆脸，内双，齐耳短发，偏白。
左侧窗户进来的阴天自然光，色温偏冷。

【独有字段】
造型：米色针织衫，素颜，头发微乱，左手腕细银链。
表情：眼神放空，嘴角下垂。
动作：趴在书桌前，手指在手机屏幕上划了一下，停住，按灭屏幕。
场景：出租屋书桌，前景摊着简历，中景人物上半身，背景窗户透进冷光。
构图：人物居中偏右，左侧留白给简历。
镜头：中景，眼平高度，轻微手持。
质感：皮肤有细微毛孔，胶片颗粒轻，低饱和偏青。
约束：人物结构正常，面部清晰不变形，五官稳定，比例自然。
负向：水印、字幕、文字、畸形手、多余人物、面部漂移、塑料感。
参数：4 秒，9:16 竖屏。
声音：环境音窗外风声；画外女声说"投了三十份，回了三个"，语气疲惫。

===== 第 2 段 · 4-9 秒 · 后续镜，全局保持 + 独有 =====

全局保持：暖调、浅景深、手持微晃、低饱和、真实生活感。28 岁女性，圆脸，内双，齐耳短发，偏白。左侧窗户进来的阴天自然光，色温偏冷。
接上一镜：按灭屏幕的手指，趴在桌上的姿势。现在——她抬头盯着天花板，发呆了两秒，右手伸过去又把手机按亮，大拇指划了两下。结尾——手指停在屏幕中央，眼睛睁大一点。

造型：同上，头发还是乱的。
表情：从放空到轻微惊讶。
动作：（上一段"接上一镜"里的就是动作：抬头→按亮手机→划两下）
场景：同上。
构图：人物居中，比上一镜稍近。
镜头：中近景，眼平高度。
质感：同上。
约束：同上。
负向：同上。
参数：5 秒，9:16 竖屏。
声音：画外女声说"后来刷到一个姑娘，镜头前说话有点生涩"，语气轻了一点。

===== 第 3 段 · 9-15 秒 · 最后一镜，全局保持 + 收尾 =====

全局保持：暖调、浅景深、手持微晃、低饱和、真实生活感。28 岁女性，圆脸，内双，齐耳短发，偏白。左侧窗户进来的阴天自然光，色温偏冷。
接上一镜：手指停在屏幕中央，眼睛睁大。现在——她坐直，对着手机镜头试了一个微笑，又放下。结尾——手指悬在屏幕上方，画面停住 2 秒。

造型：同上。
表情：从惊讶到想试试的犹豫。
场景：同上。
构图：人物居中，手在画面下沿。
镜头：中景，缓慢推近一点。
质感：同上。
约束：同上。
负向：同上。
参数：6 秒，9:16 竖屏，最后 2 秒静止。
声音：画外女声说"你要也想试试"，语气温柔。环境音淡出。
收尾：画面停住，屏幕下方浮字幕"评论区说一声"（2 秒）。
```

### 对比一下之前错的写法 vs 对的写法

| | 之前错的 | 现在对的 |
|---|---|---|
| s1 开头 | 暖调、浅景深、手持微晃...（完整） | 一样（首镜必须完整） |
| s2 开头 | 暖调、浅景深、手持微晃...（又完整写一遍） | **全局保持**：暖调、浅景深...（一行重申，不是完整段落） |
| s2 主体 | （因为开头写了完整字段，主体只能重复） | 接上一镜：...，现在...，结尾...（全是动作和状态） |
| 模型看到的 | 每段都是一个完整独立场景 → 每段开头一模一样 | 第一段完整，第二段开头一行重申共享锚点 + 明确是从上一段动作接过来 → 模型知道是同一个人、同一个世界、动作在延续 |

## 8. 三个写作规矩

- **一镜一个主动作**，最多带一个微动作（眨眼、吞咽、抬手）。
- **先写视线，再写手**：不然手会抢脸。
- **一条提示词最多两个主动作**。超过两个，模型大概率只出前一个；要更多变化就拆镜。

### 一体式写法（吃长自然语言的平台用）

有些平台（Veo / Sora / 长描述型）吃一段连贯文字，比分字段更自然。这时按"全局保持 → 共享锚点 → 动作弧线 → 独有细节"串起来：

```
全局保持：<风格锚>，<身份锚点>，<光线基调>。接上一镜：<上一镜结束状态>。<本镜动作弧线>，<造型/场景/构图/镜头>，<质感/氛围>。
```

> 各平台具体语序（即梦 / Seedance / 可灵 / 混元）：见 `prompt-templates.md`。

## 9. 时间轴：每镜从第几秒到第几秒

### 单条里的时间切片（一条 10–15 秒、里面有多个事件时用）

有些平台支持逐秒控制（Seedance / 可灵等）。把一条视频按时间切片：

```
全局保持：<风格锚>，<身份锚点>，<光线基调>。

[0-3秒]：接上一镜：<结束状态>。<本镜动作>。
[3-6秒]：<本镜动作变化>。
[6-9秒]：<本镜动作收束>。
[9-15秒]：收尾定格。

【声音】配乐 + 音效 + 对白
【参考】@图片1 首帧，@图片2 尾帧，@图片3 角色
```

规则：

- 每段只放一个动作；段与段之间状态要对上（就是 handoff 那套）。
- 总时长必须等于平台单次上限，装不下就拆。
- `@图片` / `@视频` 这种参考语法，只在平台支持时写，别硬套。

### 分镜表时间列

分镜表只写"时长"不够——剪辑、配音、字幕全都要按时间对位。

```text
| 镜号 | 时间   | 时长 | 画面 |
| s1   | 0–4s   | 4s   |
| s2   | 4–9s   | 5s   |
| s3   | 9–15s | 6s   |
```

`storyboard.json` 里对应 `start` / `end`，门禁查三条：

1. 第 N 镜的 `start` = 第 N−1 镜的 `end`（不能有空档，也不能重叠）；
2. `end − start` = `duration`；
3. 最后一镜的 `end` = `meta.duration`。

提示词开头标一段"【第 N 段 · 整条 X–Y 秒】"，用户拿去生成时知道这段排第几、接哪里。

### 时间戳精度到毫秒

不要写粗粒度（"8-16秒"），精确到毫秒，剪辑、配音、字幕才能全部对齐：

```
Shot 1: 00:00.000 – 00:04.500
Shot 2: 00:04.500 – 00:08.000
Shot 3: 00:08.000 – 00:12.000
```

### 时长怎么算

| 东西 | 占不占生成时长 |
|---|---|
| 镜头里的戏 | 占 |
| `ending` 落版 / 定格 | **不占**，叠在最后一两秒上 |

所以 `shots` 的 duration 加起来要**等于** `meta.duration`，别把落版单独扣出去。

## 10. 提示词是第一交付物，不是藏在 json 里

**这是用户吐槽的核心根因**：提示词藏在 storyboard.json 里，用户看不到、没法复制。

### 硬约束

- **每段提示词用 ```` ```text ```` 代码块包住**，标 "复制这段丢进 [即梦/可灵/Veo]"
- 每段开头标 "【第 N 段 · 整条 X–Y 秒】"
- storyboard.json 里的 prompt 字段是**备份**，不是主交付
- 不许只给 json 让用户自己找——用户不懂 json，也不想懂

### 输出格式

完整模板见 `SKILL.md` 的「输出格式」，固定三段：

1. **提示词交付**：每段一个代码块，标「第 N 段 · 整条 X–Y 秒 · 复制这段丢进 XX」
2. **台词 / 配音**：逐句台词 + 配音方式，能直接粘 TTS；空镜注明
3. **等你审**：到这一步就停，不给生成选项；用户回「可以」才进下一步
4. **怎么操作**（用户过审之后才给）：三选一——我直接出视频 / 用户自己生成（操作卡）/ 都没有（拍摄清单）

### 为什么不能只给 json

- 用户不懂 json，也不想懂
- 用户打开即梦/可灵，只需要"粘进去就能生成"的东西
- storyboard.json 是给门禁脚本和后续环节的，不是给用户看的

## 11. 详细度自检

### 机器查（`check-storyboard.py`）

- 每段有正向提示词 + 负向词 + 时长
- 首镜包含共享字段（风格锚、身份锚点、光线基调）
- 后续镜包含"全局保持"行
- 后续镜包含"接上一镜"行，且不是空话
- 每镜有「声音」段，且有配乐（BGM / 配乐）或 `no_music_reason`
- 标了 `silent` 的镜必须有 `silent_reason`
- `meta.review.story_approved` / `prompts_approved` 为 true（否则说明还没给用户审）
- 角色引用都能在角色卡里找到
- 总时长与目标时长偏差 ≤ 1 秒
- 最后一镜有收尾（定格 / 落版 / CTA）

### 人查

- [ ] 遮住提示词，只看它能不能想象出这一帧
- [ ] 后续镜开头有"全局保持"，共享锚点逐字一致
- [ ] 后续镜有"接上一镜"，写的是可见事实
- [ ] 动作有起点和终点，不是一句动词
- [ ] 光线有方向，不是"自然光"三个字
- [ ] 镜头有景别和运镜，不是"电影感"
- [ ] 每段提示词都代码块包出来了
- [ ] 故事和提示词都给用户看过，用户明确说「可以」之后才出现生成选项
- [ ] 声音三件套齐全：台词（或为什么没有）+ 环境音 + 配乐
- [ ] 完整示例对照：本文 §7 的三段提示词（首镜完整 + 后续全局保持 + 收尾）

## 12. 数据源：storyboard.json

分镜表给人看，`storyboard.json` 给门禁脚本看。两份内容必须一致。

- **字段定义**以 `assets/storyboard.template.json` 为准（含 `meta` / 角色 / `shots` / `handoffs` / `ending`），别另造结构。
- `shots[].start` / `end` / `duration` 三条时间约束见本文 §9。
- `handoffs[].match_on` 的写法见本文 §5。
- json 只是备份，用户看到的必须是代码块包出来的提示词（见 §10）。
