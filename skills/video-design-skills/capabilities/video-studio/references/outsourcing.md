# 外包给别的 AI

> 「让当前 AI 去喊用户电脑上的豆包」——本质是**把生成任务外包**。
> 技能包不能自己动手，但它能规定：什么条件能外包、走哪条通道、交什么、拿回来怎么验。

## 1. 先判断能不能外包

| 通道 | 判断条件 | 稳定性 |
|---|---|---|
| **API 直调** | 宿主有对应平台的 API Key（火山方舟 / 即梦 / 可灵） | 高，推荐 |
| **浏览器自动化** | 宿主能控制用户已登录的浏览器（CDP / 扩展） | 中，看宿主 |
| **桌面自动化** | 宿主能模拟键鼠 + 截屏（AppleScript / RPA） | 低，最后手段 |
| **用户手动** | 都没有 | 稳，但慢 |

探测顺序：**API → 浏览器 → 桌面 → 手动**。能走上面就走上面。

## 2. 外包契约（每次外包都写一份）

```yaml
task: 角色三视图
vendor: 豆包 / 即梦 / 可灵
channel: browser          # api | browser | desktop | manual
input: |
  【完整的指令原文，不压缩】
expect:
  files: 3                # 三张图
  format: png
  naming: girl-front / girl-side / girl-back
  output_dir: media/characters/girl/
verify:
  - 三张是同一人，发型和服装一致
  - 纯白背景，无文字和水印
  - 正面、侧面、背面都能看清
fallback: 重试 1 次 → 不行退回「手动话术」
```

## 3. 各通道怎么做

### API 直调

1. 先确认宿主有没有对应 Key（看工具表 / 环境变量）。
2. 没有就问用户：「你有没有火山方舟 / 即梦的 API Key？没有的话我用别的方式。」
3. 调用前说清楚会花钱：「这一步要调 API，按量计费，继续吗？」
4. 拿到结果落盘，回填 `storyboard.json`。

**不许做**：没有 Key 就假装能调。

### 浏览器自动化

1. 先探测：宿主能不能连上用户的浏览器（而不是自己起一个空的）。
2. 能连 → 打开豆包 / 即梦页面，确认已登录。
3. 输入指令 → 等生成 → 下载 → 落盘。
4. 关掉自己开的 tab，不留垃圾。

**注意**：用第三方服务自动化可能违反其条款，先提示一句；登录态属于用户，不要碰。

### 桌面自动化

只做最后手段。AppleScript 打开 App、粘贴、回车、截图。每一步都可能卡住，**别做成主路径**。

### 用户手动（兜底）

给他一段能直接复制的话（见 `assets/ask-ai.md`），让他自己喊。

## 4. 拿回来之后验什么

- [ ] 数量对不对（三视图就是三张）
- [ ] 是不是同一个角色
- [ ] 有没有水印、文字、奇怪的手指
- [ ] 背景符不符合要求（纯白 / 场景）
- [ ] 尺寸和比例能用

不合格就按 `failure-diagnosis.md` 处理，别硬用。

## 5. 交接给下游

外包产物落 `media/`，在 `storyboard.json` 里回填：

```json
{"character_refs": ["girl"], "ref_images": ["media/characters/girl/girl-front.png"]}
```

下一镜引用同一个角色 id 和同一批参考图。

## 6. 别做的事

- 没有 Key 却说能调。
- 用用户没登录的浏览器冒充已登录。
- 外包了不写契约、不验结果，直接把图塞进分镜。
- 一次外包五个任务——一次一个，拿到再下一个。
