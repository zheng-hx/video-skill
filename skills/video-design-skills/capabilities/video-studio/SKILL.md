# 文案转视频工坊（video-studio）

> 输入是**文案**，不是故事。先判断文案类型（故事型走展开，广告型从零补写），再拆分镜、写提示词、最后才是生成。
> **用户只用人话描述，其余全归技能**：判类型、选平台、定时长、配声音、跑门禁、记审批、真去生成，都是技能的事。
> 多段**用全局保持**——共享锚点（风格、长相、光线）每段重申，但只一行，不重写完整段落。

## 什么时候用

- 用户手里有文案（或刚在本会话里生成过），说「做成视频」「出个分镜」「生成提示词」
- 用户说「多段视频怎么接」「人物别换脸」「前后对不上」
- 用户没给文案，只说「做个面膜视频」——就按这个意思直接写一版，写完给他改，不先问风格 / 平台 / 时长

## 第一轮：只做一件事

用户说「做个视频 / 生成视频 / 生成文案故事」时，**先判断有没有文案**，别急着问风格、工具、主题：

| 用户给了什么 | 第一轮做什么 | 不许做什么 |
|---|---|---|
| 只有「做视频」三个字 | 问**一句**：「先给你写一版文案，还是你已经有文案贴过来？」 | 不许列主题选项，不许问风格 / 工具 |
| 主题或品类（"面膜""招主播"）但没文案 | 交给 `copy-video-studio` 出 `script.md` | 不许跳过文案直接拆分镜 |
| 已有文案 | 直接进故事（Stage 1），给完整故事 | 不许再问一遍平台 / 时长 / 风格 |
| 说「文案 + 视频」 | 先文案，再视频，两步走 | 不许合并成一次问卷 |

**选项只能来自用户自己的话。** 不许给主题菜单（IP 名、项目名、"某短片"），不许一次抛 Q1/Q2/Q3——一轮只问一个，问完就停。

- ❌ Q1 主题：「萌乐园 IP 短片 / 品牌故事 / 情感生活 / 其他」——用户没提，编出来只会干扰他
- ❌ 一次问主题 + 风格 + 生成方式——用户只想做一件事，甩三个问题他就跑了

## 不做什么

- 不写营销文案本体（交给 `copy-video-studio`；这里只做简版兜底）
- 不假装出了成片：没有生成能力就交提示词包 + 制作包
- 不引入 `project.json`、审阅看板、五态状态机那种重流程——只留一份 `storyboard.json` 做数据源

## 七条铁律

1. **角色卡为视频重新设计，不是从文案抄。** 文案说"我有个朋友"，视频要给她**视觉上有辨识度的角色**——发型走向、发色、标志性特征（梨涡/眼镜）都要写。
2. **按情绪/节奏阶段拆，不是按字数硬算。** 一个情绪阶段一段，每段 8–10 秒。情绪阶段数优先，字数/时长只是兜底。
3. **negative 针对风格精准拦。** AI 漫剧拦"真实照片感/3D渲染"，真人拦"漫画感/插画感"。别写模糊的"不要 AI 感"。
4. **handoff 必须写 match_on。** 至少 2 个（wardrobe + lighting），告诉模型哪些维度必须跟上一段对得上。
5. **提示词是第一交付物。** 每段代码块包出来，不许藏在 json 里让用户自己找。
6. **声音三件套，缺一样不算写完**——台词 + 环境音 + 配乐。写法见「声音」节，故事里有人说话就不许出「无台词」。
7. **每段先给用户看，没明确说「可以」不许往下走。** 不许拿「10 秒没说话就当同意」替用户点通过。

## 用户只说人话，其余都归技能

默认用户：不懂开发、不懂 AI、不会装东西、不会跑命令、也不想学平台。他描述想要什么，剩下的技能全包。

| 用户做 | 技能做 |
|---|---|
| 用一句人话说要什么（「做个面膜视频」「把这段文案做成视频」） | 判类型、写或读文案、写故事、拆分镜、写提示词、选平台、定时长、配声音 |
| 看结果，说「可以」或者「这里改改」 | 摊开故事和提示词、记审批、跑门禁、真去生成、把成片交回来 |
| 用大白话说哪不对 | 定位改哪、只重跑坏的那段、再交回来 |

**用户只需做三个动作**：说要什么、说「可以」、说哪不对。除此之外不许让他跑命令、看报错、配环境、选平台、拼参数、自己找文件、自己复制粘贴。

真做不了（比如这个环境没有生成工具）就**明说一句**「这里出不了成片，提示词给你，拿到哪个平台都能用」——这是能力限制，不是甩一道选择题给用户。

| 不要 | 要 |
|---|---|
| 说「分镜」「handoff」「提示词工程」「字段」 | 说「画面」「怎么接」「给 AI 的描述」 |
| 让他跑 `python3 ...` / 看报错 / 配环境 | 技能自己跑、自己验，只把结果给他 |
| 问「用什么模型」「哪个平台」「什么画幅」「怎么生成」 | 自己能判的全按默认，做完再说 |
| 给一堆文件让他自己找、自己拼 | 能生成就生成，出不了就明说，别把活推回去 |
| 一轮问三个问题 | 一轮最多问一句 |

## 问不问：看知不知道

| 情况 | 怎么处理 |
|---|---|
| 已知 / 能推断 | 不问，直接用；推断的打标 |
| 不知道，缺了会返工 | 必须问，问完再动 |
| 不知道，但不影响主线 | 不问，按默认，标出来 |

**默认值先走，别拿它们当开场问题**：

- **风格**：默认真人实拍感（最通用，口型对得上）。只有到写提示词那一步、内容又偏故事/情感时，才问**一句**「真人拍的那种，还是动漫那种？」二选一——刚接活时不问。
- **目标工具**：默认即梦，不问。用户自己说「用可灵 / Veo」才切。
- **生成方式**：不问。有没有生成能力自己探测（见 `production-route.md`）；探不到就给提示词包，不要让用户选「本环境生成 / 输出提示词」。

**唯一必问**：连「讲什么」都没有时，问一句「这条想讲什么？」。除此之外，先按默认给一版。

文案改一版便宜，视频生成一次贵，所以故事的确认要比文案多——这不是啰嗦，是省钱。

## 委派规则

三段流水线（文案 → 故事 → 提示词 → 生成），交接按 `references/workflow-protocol.md` 走。要点：

- **没文案又要做视频**：交给 `copy-video-studio` 出 `script.md`；只有临时需求才用简版兜底。
- **有 `story.md` 就读它**起步，不重问已知；只有文案就自己写完整故事，**不许跳过故事直接拆分镜**。
- **交出去带三样**：交接物、已确认设定、未决项。
- **产物一律落盘**：`output/<日期>-<slug>/` 下放 `script.md` / `story.md` / `storyboard.json`，路径直接告诉用户。

## 完整流程

### 意图路由

```
用户输入
  ├─ "只要文案/不要视频" → 文案分支 → 结束
  └─ "要做视频" 或 文案+视频 → 视频分支 → 完整流水线
```

### 文案分支（只要文案）

`Stage 1 文案（copy-video-studio 产出）→ 自审 → 用户审 → approve → ✅ 结束`

自审直接复用 `copy-video-studio` 的红线：限流词黑名单替换过、钩子点是具体画面、结果没编数字、CTA 只有一个。

**用户审核**："这个方向对不对？有没有我不想要的？"→ approve 后结束，不进入 Stage 2 以后。

### 视频分支状态机

```
Stage 1 故事 → Stage 2 补丰满 → Stage 3a 参考图 → Stage 3b 视频提示词
  → Stage 3c 试跑诊断 → Stage 3d 迭代 → Stage 4 生成/交付
```

每个 Stage 内部：`draft（产出）→ 自审 → 用户审核 → approved 进下一个 / rejected 回当前 Stage 重写`。

**回退规则**：用户不满意就回当前 Stage 重写，之前已 approve 的产物不动。

### 审核闸门（硬）

「用户审核」**只有用户明确说「可以 / 没问题 / 继续」才算过**。

- 不许自己替用户 approve；用户没表态就停在这一段。
- 「用户 10 秒内没说改就自动通过」——**已删除**，那是跳步的开关。
- **故事（Stage 1）和提示词（Stage 3b）必须给用户看**：这两段决定整条片子的方向和钱。
- 没过审核之前，**不许出现生成选项 / 操作卡 / 「复制这段丢进即梦」**。

**用户只做一个动作：在聊天里说「可以」。** 命令由技能自己跑——用户不懂技术，不需要开终端、记路径、敲 `python3`。

| 谁来做 | 做什么 | 记录成什么 |
|---|---|---|
| **技能**（默认） | 把故事和每段提示词摊给用户看 → 他说「可以」→ 技能跑 `approve.py --file <storyboard.json> --chat --quote "<他的原话>"` | `approved_by: user-chat` + `confirmed_quote`（用户原话） |
| 用户（可选） | 用户自己想亲自签，才让他开终端跑 `approve.py --file <storyboard.json>` 输「可以」 | `approved_by: user-tty` |

顺序固定：**先摊开 → 用户说「可以」→ 技能跑 approve → 再跑 `check-storyboard.py <storyboard.json>`**，红就是红、绿就是绿。

**红线**：不许自己往 `meta.review` 写 `content_hash`，不许编 `confirmed_quote`，不许拿 `--no-strict` 蒙过去。
`content_hash` 覆盖所有提示词，审批后改任何一句都会对不上、审批自动作废。

### Stage 1 故事：自审清单 + 红线

| # | 自审项 | 红线（过不了就重写） |
|---|---|---|
| 1 | 一句话能不能讲清楚 | ❌ "电竞桌面有古风角色破壁"这种纯视觉描述，没有人物/情感/转折 |
| 2 | 有没有起承转合三幕 | ❌ 只有"电竞→破壁"，没有铺垫和落点 |
| 3 | 有没有情感弧线 | ❌ "破壁了就完了"，没有人物状态变化 |
| 4 | 有没有钩子点 | ❌ 没有具体的动作/数字/反差让观众记住 |
| 5 | 同一场景能演完吗 | ❌ 故事本身需要换 3 个以上场景（除非用户明确要求） |
| 6 | 限流词黑名单过了吗 | ❌ 有"招主播""底薪""月薪""简历"等没替换 |
| 7 | 结果有没有编数字 | ❌ 有具体收入数字、夸大的对比贬损 |
| 8 | 有没有一句观众自己说过的话（共鸣） | ❌ 全是「我很迷茫」「她哭了」这类总结和情绪结果，观众插不进去 |
| 9 | 钱有没有出现 | ❌ 通篇不提钱，观众不知道值不值得试；也❌ 写「月入过万」这类数字承诺 |
| 10 | 有没有 AI 腔 | ❌ 「不是…而是…」对仗句、「迷茫 / 焦虑 / 内耗」、「后来我明白了」 |

**用户审核要审什么**："这个故事对不对？主角是不是你要的？情感弧线是不是你想要的？"（审方向，不审台词美不美）

### Stage 2 补丰满：自审清单 + 红线

| # | 自审项 | 红线 |
|---|---|---|
| 1 | 每一幕能不能直接变成镜头 | ❌ "他很沮丧"——沮丧是什么表情？什么动作？ |
| 2 | 事件链有因果吗 | ❌ 从"加班"直接跳到"破壁"，中间没有触发点 |
| 3 | 人物状态变化有具体细节吗 | ❌ "疲惫→震惊"——表情怎么变？眼睛睁多大？身体有没有动？ |
| 4 | 时间流动有道具证据吗 | ❌ 没有任何道具变化体现时间流逝 |
| 5 | 钩子点都是画面不是旁白吗 | ❌ 钩子点全在旁白里说，没有画面演 |
| 6 | 和 Stage 1 故事不矛盾吗 | ❌ Stage 1 说"男主加班"，Stage 2 补成"女主加班" |

**用户审核**："这些细节对不对？有没有我不想要的？有没有漏掉我想要的？"

### Stage 3a 参考图：自审清单 + 红线（必须用户 approve）

| # | 自审项 | 红线 |
|---|---|---|
| 1 | 人物全脸清晰可辨 | ❌ 脸被头发挡、角度偏、有遮挡物 |
| 2 | 双手完整可见 | ❌ 手不在画面里、手被挡、手畸形 |
| 3 | 服装细节和 Stage 2 一致 | ❌ Stage 2 说"黑色挂脖针织"，图出成"白色宽松T恤" |
| 4 | 光线色调和 Stage 2 一致 | ❌ Stage 2 说"冷青色调"，图出成"暖橙色调" |
| 5 | 反向约束独立成块 | ❌ 反向约束散在末尾没单独标 |
| 6 | 摄影级风格锚写了 | ❌ 只有"暖调"没有"Arri Alexa Mini 质感+35mm 胶片+暖黄偏绿调色" |

**用户审核**："这个人物/场景是不是我要的？"——参考图必须用户说"可以"才能进 Stage 3b。

### Stage 3b 视频提示词：自审清单 + 红线

| # | 自审项 | 红线 |
|---|---|---|
| 1 | 按用户选的平台语法写了吗 | ❌ 可灵用了即梦的语序（镜头放最前） |
| 2 | 风格锚和参考图一致 | ❌ 参考图"暖黄偏绿"，提示词出成"冷青色调" |
| 3 | 人物和参考图严格一致 | ❌ 又写一遍人物细节——应写"与参考图严格一致" |
| 4 | 时间戳精确到毫秒 | ❌ 只写"8-16秒" |
| 5 | 台词带语言标签（可灵） | ❌ 可灵没写 `<d>[Chinese]</d>` |
| 6 | 声音三件套齐（见「声音」节） | ❌ 只写"加个BGM" |
| 7 | 反向约束独立成块 | ❌ 没单独标 |
| 8 | 多镜头衔接：match_on 写了吗 | ❌ handoff 里没有 match_on |
| 9 | 提示词代码块包出来了 | ❌ 藏在 json 里没直接给 |
| 10 | 台词 / 配音单独给了一份，能直接粘 TTS | ❌ 只有 prompt，没有可粘的台词表 |
| 11 | 内容自审全绿：`check-storyboard.py <file> --content-only` | ❌ 门禁报错（审批位此时还没签，正常） |

**用户审核**："这些提示词能直接丢进平台用吗？有没有哪里要调？"

---

### Stage 3c 试跑诊断（必须用户 approve）

Stage 3b 出完**不是终点**——先用参考图 + 提示词跑一次 3–5 秒试生成，按症状表诊断：

| 试跑结果 | 改哪里 |
|---|---|
| 人物换脸 | 提示词最前加"主角与参考图严格一致，五官/发型/服装/肤色不得漂移"；平台里把参考图权重拉到 80%+ |
| 表情不对 | 只改那一段表情："嘴角上扬"→"嘴角明显上扬，右侧梨涡清晰，眼睛弯成月牙" |
| 动作跳了 | handoff 的 match_on 没跟上：补结束状态和下一镜起始状态，中间加过渡动作 |
| 风格漂了 | 后续镜"全局保持"里补风格锚关键元素（如"Arri Alexa Mini 质感、暖黄偏绿调色"） |
| 屏幕里没有人物 | 主体描述放太后面：把主体移到提示词最前面 |
| 多了人 / 多了灯 | 反向约束加"不要任何额外人物、不要多余家具、不要额外光源" |
| 手部畸形 | 提示词最前补"双手完整可见，结构正常" |
| 文字 / 水印 | 反向约束加"不要任何文字、水印、logo" |

**用户审核**："试跑出来有没有我不能接受的问题？"→ 可以就进 Stage 4；要改就进 Stage 3d。

---

### Stage 3d 迭代（最多 3 次）

1. **定向修改，不重写**：哪段飘了改哪段，对的不动。
2. **每次只改一个变量**：人物不对改人物，风格不对改风格锚，别同时改五件事。
3. **最多 3 次**：3 次还不对，说明故事本身有问题，回 Stage 2 重写。

迭代后终检：和参考图风格锚一致、和 Stage 2 事件链一致、`check-storyboard.py <file> --content-only` 全绿。然后回 Stage 3c 再试跑。

## 一致性三件套

| 要保的 | 靠什么 |
|---|---|
| 人物一致 | 共享身份锚点（逐字不变），造型变化写进状态表 |
| 剧情一致 | 连续性状态表 + 每镜"接上一镜"的首尾状态 |
| 画面衔接 | handoff 合同 + 全局保持重申 + 首尾帧链 |

## 声音：三件套，缺一样不算写完

视频模型大多不出台词，声音必须**单独交付一份**：一段给模型（环境音 + 配乐），一段给 TTS / 真人录音（台词）。

| 要写的 | 写在哪 | 不写会怎样 |
|---|---|---|
| 台词 / 配音 | 每镜 `line` + prompt 的「声音」段；再单独给一份「台词 / 配音」 | 人物嘴不动，整条没信息 |
| 环境音 | prompt 的「声音」段：底噪 + 动作音 + 呼吸/静默 | 无声片，像 PPT |
| 配乐 | prompt 的「声音」段：进入 / 叠层 / 音量 / 收束（`non_diegetic_music`） | 情绪起不来 |

- **故事里有人在说话**（口播 / 对白 / 独白 / 对着镜头录视频）→ 每镜必须有台词，**不许写「无台词」**。
- 真没有台词的镜头（空镜 / 环境特写）：`silent: true` + `silent_reason` 写清楚为什么。
- 真不要配乐（现场感 vlog）：`no_music_reason` 写清楚，不许默认省略。
- 即梦声音支持有限，声音要后期配或 TTS——台词表是**独立交付物**，不是 prompt 里一句「有台词」就算数。

**写提示词前先抽台词表**：把 `story.md` 里每句要说的话逐句抄出来（口播 / 对白 / 独白），标上「谁说、落在哪一镜」。故事里有人在说话，就**不存在「无台词」**，只存在「你漏抄了」。

## 提示词是第一交付物

硬约束：

- 每段提示词用 ` ```text ` 代码块包住，标清「第几段 · 整条第几秒到第几秒」
- 能生成就技能自己生成；出不了片时，这段代码块就是用户拿了能直接用的成品，不用他再拼
- `storyboard.json` 是备份，不是主交付；不许只给 json 让用户自己找
- 多段时，第 2 段起开头写一行「全局保持：…」+ 一行「接上一镜：…」，其余独有字段照常写全

> 模式：单条提示词 / N 段分镜

===== 提示词交付 =====

【第 1 段 · 整条 0–4 秒】

【第 2 段 · 整条 4–9 秒】

## 门禁

技能自己跑 `check-storyboard.py` 验，**不让用户跑命令、不把报错给他看**。两步：

- **用户审核前**：`check-storyboard.py <file> --content-only` —— 内容必须全绿
- **审批签好后**：`check-storyboard.py <file>` —— 内容 + 审批指纹都必须绿

**结构**：每镜有 `prompt`（≥60 字）、`negative`、`duration`（>0 且 ≤ `meta.max_shot_duration`）、`beat`；时间轴 `start`/`end` 连续且与 `duration` 对得上；`meta.authorization` 四个字段必填，`pending` 直接拦。

**提示词质量**：每镜要有镜头词（景别/运镜）、光线词、构图词、质感词、约束层；不许「电影感/氛围感/高级感」这类模糊词；`prompt` 里不许出现「保持连续/同上/同前/照旧」这类衔接空话，也不许正向要「水印/二维码/logo」而负向又写不要。

**首镜 vs 后续镜**：首镜完整写风格锚 + 身份锚点 + 光线词；后续镜用「全局保持：」重申风格锚 + 光线，用「接上一镜：」写上一镜结束状态。

**负向词**：每镜 `negative` 必须含「二维码 / logo / 水印」三个画面红线。

**衔接**：非最后一镜都有 handoff，`match_on` ≥ 2，`end_state` / `next_start_state` 是可见事实、不含空话；角色引用都能在角色卡里找到。

**台词与声音**：每镜有「声音」段 + 配乐（或 `no_music_reason`）；`silent` 镜有具体的 `silent_reason`；全片无台词必须写 `meta.no_dialogue_reason`。**同目录有 `story.md` 时门禁会自动做台词对账**——故事里有引号台词 / 口播 / 对白，分镜却一句 `line` 都没有，直接判台词漏了。

**台词密度**：门禁按最长单句算语速，超过 8 字/秒判「说不完」（正常口播 5–6 字/秒）。写词时按这个反推时长：20 字的一句话至少要 4 秒，别硬塞进 2 秒的镜头。

**收尾**：总时长偏差 ≤ 1 秒；最后一镜有收尾（定格 / 落版 / CTA），`ending.end_state` 是可见画面。

## 生成前强制检查（少一条都不许进生成）

1. **故事和提示词都给用户看过了**，是用户本人说的「可以」，并已用 `approve.py` 记录审批
2. **台词没漏**：故事里有人说话的镜头 `line` 都填了；全片 silent 的有具体 `no_dialogue_reason`，且台词对账通过
3. **声音三件套齐**：每镜有「声音」段，有配乐或具体的 `no_music_reason`
4. **平台语法对**：按技能定下的平台写（默认即梦；用户自己提了才换。即梦/可灵/Seedance/Veo 语序不同）
5. **门禁全绿**：`check-storyboard.py` 跑出 `[PASS]`
6. **生成方式由技能自己定，且和行为一致**：能生成就直接出片，不许偷偷换成给提示词包；真出不了就当场说明，不许让用户选

## 失败怎么办

- 门禁红了：按报错改字段，改完重跑。
- 画面不对：按 `references/failure-diagnosis.md` 的症状表定位，只重跑出问题那一段。
- 多段串不起来：先看后续镜有没有「全局保持」和「接上一镜」；有了还不行就补首尾帧参考。
- 同一问题重试最多 2 次，还不行就换策略（换平台 / 拆镜 / 降级）或把未解决项列给用户，别烧额度。
- 根因在故事就回去改 `story.md`，重跑一百次也没用。
