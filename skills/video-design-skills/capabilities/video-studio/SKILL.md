# 文案转视频工坊（video-studio）

> 输入是**文案**，不是故事。先判断文案类型（故事型走展开，广告型从零补写），再拆分镜、写提示词、最后才是生成。
> 提示词**直接给**——每段代码块包出来，用户复制丢进即梦/可灵/Veo就行。
> 多段**用全局保持**——共享锚点（风格、长相、光线）每段重申，但只一行，不重写完整段落。

## 什么时候用

- 用户手里有文案（或刚在本会话里生成过），说「做成视频」「出个分镜」「生成提示词」
- 用户说「多段视频怎么接」「人物别换脸」「前后对不上」
- 用户没给文案，只说「做个面膜视频」——先反问一句是「我按你的意思写一版文案」还是「你贴文案」，二选一，别自己编完再问

## 不做什么

- 不写营销文案本体（交给 `copy-video-studio`；这里只做简版兜底）
- 不假装出了成片：没有生成能力就交提示词包 + 制作包
- 不引入 `project.json`、审阅看板、五态状态机那种重流程——这里只留一份 `storyboard.json` 做数据源

## 五条铁律

1. **角色卡为视频重新设计，不是从文案抄。** 文案说"我有个朋友"，视频就要给她一个**视觉上有辨识度的角色**——发型走向、发色、标志性特征（梨涡/眼镜）都要写。
2. **按情绪/节奏阶段拆，不是按字数硬算。** 一个情绪阶段一段，每段 8-10 秒，表情能精确到位。情绪阶段数优先，字数/时长只是兜底。
3. **negative 针对风格精准拦。** AI 漫剧拦"真实照片感/3D渲染"，真人拦"漫画感/插画感"。别写模糊的"不要 AI 感"。
4. **handoff 必须写 match_on。** 至少 2 个（wardrobe + lighting），告诉模型哪些维度必须跟上一段对得上。
5. **提示词是第一交付物。** 每段代码块包出来，用户复制丢进即梦/可灵就行。不许藏在 json 里让用户自己找。

## 用这套东西的人，可能什么都不懂

默认用户：不懂开发、不懂 AI、不会装东西、不会跑命令。他不是来学技能的，是来拿结果的。

| 不要 | 要 |
|---|---|
| 说「分镜」「handoff」「提示词工程」「字段」 | 说「画面」「怎么接」「给 AI 的描述」 |
| 让他跑 `python3 ...` / 看报错 / 复制一长串配置 | 技能自己跑、自己验，只把结果给他 |
| 问「用什么模型」「哪个平台」「什么画幅」 | 问「想要真人拍的那种，还是动漫那种？」 |
| 给他一堆文件让他自己找 | 提示词每段代码块包出来，直接让他复制 |
| 一轮问三个问题 | 一轮只让他做一个动作 |

**每轮只让用户做一个动作**：答一句话、点一下、或者复制一次。超过一个他就跑了。

## 问不问：看知不知道

| 情况 | 怎么处理 |
|---|---|
| 已知 / 能推断 | 不问，直接用；推断的打标 |
| 不知道，缺了会返工 | 必须问，问完再动 |
| 不知道，但不影响主线 | 不问，按默认，标出来 |

**必问项**：风格、目标工具。这两个缺一个都会返工。

- **风格默认值**：真人实拍感（最通用，表情自然，口型能对上）。故事型/情感型内容建议额外给一个 AI 漫剧选项（漫剧表情更夸张、背景叠层更好做），二选一让用户确认。别只给一个选项。
- **目标工具默认值**：即梦（最通用，中文友好）。用户没说就按即梦格式出，通用性好。

文案改一版便宜，视频生成一次贵，所以故事的确认要比文案多——这不是啰嗦，是省钱。

## 委派规则

这套技能是三段流水线（文案 → 故事 → 提示词 → 生成），交接按本技能内的 `references/workflow-protocol.md` 走。要点：

- **没文案又要做视频**：交给 `copy-video-studio` 出 `script.md`；只有临时需求才用简版兜底。
- **有 `story.md` 就读它**起步，不重问已知；只有文案就自己写完整故事，**不许跳过故事直接拆分镜**。
- **交出去带三样**：交接物、已确认设定、未决项。
- **没有文件能力**：贴完整文本，标「复制走」，不假装落盘。

## 完整流程：状态机 + 门禁 + 红线 + 审核

### 意图路由（**先判断用户要什么，再走对应分支**）

```
用户输入
  ├─ "只要文案/不要视频" → 文案分支 → 结束
  └─ "要做视频" 或 文案+视频 → 视频分支 → 完整流水线
```

---

### 文案分支（**只要文案，不要视频**）

```
用户输入 → Stage 1 文案（copy-video-studio 产出）→ 自审 → 用户审 → approve → ✅ 结束
```

**Stage 1 文案自审清单**（复用 copy-video-studio 的红线）：
| # | 自审项 | 红线 |
|---|---|---|
| 1 | 故事型骨架（转折由"我们"完成：有引路人、有公司具体动作，观众看完想联系你们） | ❌ 只有钩子→痛点→卖点的广告骨架，或主角自己试成功 |
| 2 | 限流词黑名单过了 | ❌ 有"招主播""底薪""月薪""简历"等没替换 |
| 3 | 钩子点都是具体画面 | ❌ "让你心动"这种抽象话 |
| 4 | 结果没编数字 | ❌ 有具体收入数字 |
| 5 | CTA 只有一个 | ❌ "私信+加微信+评论"三个 CTA |

**用户审核要审什么**："这个方向对不对？有没有我不想要的？"→ approve 后自动结束，不进入 Stage 2 以后。

---

### 视频分支（**要视频，完整流水线**）

#### 状态机

```
Stage 1 故事 → Stage 2 补丰满 → Stage 3a 参考图 → Stage 3b 视频提示词 → Stage 3c 试跑诊断 → Stage 3d 迭代 → Stage 4 生成/交付
  ↑ rejected        ↑ rejected        ↑ rejected         ↑ rejected       ↑ 诊断飘了    ↑ 迭代完
  └────────── 回当前 Stage 重写，之前 approve 的不动 ─────────────────────────────────────┘
```

每个 Stage 内部状态：
```
draft（产出）→ 自审（自动过检查清单）→ 用户审核 → approved（进下一个）/ rejected（回当前 Stage 重写）
```

**回退规则**：用户说不满意，回到当前 Stage 重写，之前已经 approve 的 Stage 产物不动。比如用户对 Stage 2 补丰满的结果不满意，回 Stage 2 重写，Stage 1 的故事保持不变。

**自动 approve 规则**：用户 10 秒内没说"改"，视为 approve，自动进入下一个 Stage。但**Stage 3a 参考图和 Stage 3c 试跑**除外——这两个必须用户明确说"可以/没问题"才能过，不能自动 approve（因为生成成本高）。

---

### Stage 1 故事：自审清单 + 红线

| # | 自审项 | 红线（过不了就回 Stage 1 重写） |
|---|---|---|
| 1 | 一句话能不能讲清楚 | ❌ "电竞桌面有古风角色破壁"这种纯视觉描述，没有人物/情感/转折 |
| 2 | 有没有起承转合三幕 | ❌ 只有"电竞→破壁"，没有前面的铺垫和后面的落点 |
| 3 | 有没有情感弧线 | ❌ "破壁了就完了"，没有人物状态变化 |
| 4 | 有没有钩子点 | ❌ 没有具体的动作/数字/反差让观众记住 |
| 5 | 同一场景能演完吗 | ❌ 故事本身需要换 3 个以上场景（除非用户明确要求） |
| 6 | 限流词黑名单过了吗 | ❌ 有"招主播""底薪""月薪""简历"等限流词没替换 |
| 7 | 结果有没有编数字 | ❌ 有具体收入数字、夸大的对比贬损 |

**用户审核要审什么**："这个故事对不对？主角是不是你要的？情感弧线是不是你想要的？"（不是审台词美不美，是审方向对不对）

---

### Stage 2 补丰满：自审清单 + 红线

| # | 自审项 | 红线 |
|---|---|---|
| 1 | 每一幕能不能直接变成镜头 | ❌ "他很沮丧"——沮丧是什么表情？什么动作？ |
| 2 | 事件链有因果吗 | ❌ 从"加班"直接跳到"破壁"，中间没有触发点（喝咖啡？手碰到显示器？） |
| 3 | 人物状态变化有具体细节吗 | ❌ "疲惫→震惊"——表情怎么变？眼睛睁多大？身体有没有动？ |
| 4 | 时间流动有道具证据吗 | ❌ 没有任何道具变化体现时间流逝 |
| 5 | 钩子点都是画面不是旁白吗 | ❌ 钩子点全在旁白里说，没有画面演 |
| 6 | 补写的内容和 Stage 1 故事不矛盾吗 | ❌ Stage 1 说"男主加班"，Stage 2 补成"女主加班" |

**用户审核要审什么**："这些细节对不对？有没有我不想要的？有没有漏掉我想要的？"

---

### Stage 3a 参考图：自审清单 + 红线（**必须用户明确 approve，不能自动过**）

| # | 自审项 | 红线 |
|---|---|---|
| 1 | 人物全脸清晰可辨 | ❌ 脸被头发挡、角度偏、有遮挡物 |
| 2 | 双手完整可见 | ❌ 手不在画面里、手被挡、手畸形 |
| 3 | 服装细节和 Stage 2 一致 | ❌ Stage 2 说"黑色挂脖针织"，参考图出成"白色宽松T恤" |
| 4 | 光线色调和 Stage 2 一致 | ❌ Stage 2 说"冷青色调"，参考图出成"暖橙色调" |
| 5 | 反向约束独立成块 | ❌ 反向约束散在末尾没单独标 |
| 6 | 摄影级风格锚写了 | ❌ 只有"暖调"没有"Arri Alexa Mini 质感+35mm 胶片+暖黄偏绿调色" |

**用户审核要审什么**："这个人物/场景是不是我要的？有没有哪里不对？"——**参考图必须用户说"可以"才能进 Stage 3b**，不能自动 approve。

---

### Stage 3b 视频提示词：自审清单 + 红线

| # | 自审项 | 红线 |
|---|---|---|
| 1 | 按用户选的平台语法写了吗 | ❌ 可灵用了即梦的语序（镜头放最前） |
| 2 | 风格锚和参考图一致 | ❌ 参考图是"暖黄偏绿调色"，视频提示词出成"冷青色调" |
| 3 | 人物和参考图严格一致 | ❌ 视频提示词又写了一遍人物细节——应该写"与参考图严格一致" |
| 4 | 时间戳精确到毫秒 | ❌ 只写了"8-16秒" |
| 5 | 台词带语言标签（可灵） | ❌ 可灵没写 `<d>[Chinese]</d>` 标签 |
| 6 | 声音设计两段独立 | ❌ 只写了"加个BGM" |
| 7 | 反向约束独立成块 | ❌ 没单独标 |
| 8 | 多镜头串起来：match_on 写了吗 | ❌ handoff 里没有 match_on |
| 9 | 提示词代码块包出来了 | ❌ 藏在 json 里没直接给 |
| 10 | check-storyboard.py 全绿 | ❌ 门禁脚本报错 |

**用户审核要审什么**："这些提示词能直接丢进平台用吗？有没有哪里要调？"

---

### Stage 3c 试跑诊断（**必须用户明确 approve，不能自动过**）

Stage 3b 提示词出完了，**不是终点**——先用参考图 + 提示词跑一次 3 秒试生成，诊断问题。

**试跑怎么操作**：用户拿 Stage 3a 的参考图和 Stage 3b 的提示词，去即梦/可灵/混元跑一次最短时长的生成（3-5 秒），截一张/录一小段反馈。

**skill 拿到反馈后按这个诊断表分析**：

| 试跑结果 | 诊断 | 改哪里 |
|---|---|---|
| 人物换脸了 | 参考图权重不够或没在提示词最前强调 | 提示词最前面加"主角与参考图严格一致，五官/发型/服装/肤色不得漂移"；平台里把参考图权重拉到 80%+ |
| 表情不对（该笑没笑） | 情绪描述不够具体 | 只改那一段的表情描述："嘴角上扬"→"嘴角明显上扬，右侧梨涡清晰可见，眼睛弯成月牙形" |
| 动作跳了 | handoff 的 match_on 没跟上 | 补上一段结束状态和下一段起始状态，中间加过渡动作 |
| 风格漂了 | 后续镜"全局保持"没加关键风格锚 | 在后续镜开头的"全局保持"里加上风格锚关键元素（如"Arri Alexa Mini 质感、暖黄偏绿调色"） |
| 屏幕里没有人物 | 主体描述放太后面（可灵尤其吃这个） | 把主体移到提示词最前面 |
| 多了东西（多了人/多了灯） | 反向约束不够 | 反向约束里加"不要任何额外人物、不要多余家具、不要额外光源" |
| 手部畸形 | 没强调"双手完整可见" | 在提示词最前面补"双手完整可见，结构正常" |
| 文字/水印 | 反向约束漏了 | 加"不要任何文字、水印、logo" |

**用户审核要审什么**："试跑出来有没有我不能接受的问题？"→ 没问题说"可以"就进 Stage 4；有问题说"改"就进 Stage 3d。

---

### Stage 3d 迭代（**最多 3 次，定向修改不重写**）

**迭代原则**：
1. **定向修改，不重写**：哪段飘了改哪段，对的不动
2. **每次只改一个变量**：人物不对改人物描述，风格不对改风格锚，不要同时改五件事
3. **最多迭代 3 次**：3 次还不对，说明故事本身有问题，回 Stage 2 重写

**迭代后终检**：
- 和 Stage 3a 参考图的风格锚一致吗
- 和 Stage 2 的事件链/钩子点/人物状态变化一致吗
- 自审清单再跑一遍全绿吗

迭代完回到 Stage 3c 再试跑一次，直到通过。

### 一句话概括

**文案分支**：Stage 1 → 自审 → 用户审 → 结束
**视频分支**：Stage 1 故事 → Stage 2 补丰满 → Stage 3a 参考图（必须手动 approve）→ Stage 3b 提示词 → Stage 3c 试跑诊断（必须手动 approve）→ Stage 3d 迭代（最多 3 次）→ Stage 4 生成/交付

每个环节产出 → 自审 → 用户审 → approve 进下一个 / rejected 回当前重写。红线是不能碰的底线。

**声音单独交付**：视频模型大多不出台词，所以【台词 / 配音】必须单独给一份，给 TTS 或真人录音用。

## 一致性三件套

| 要保的 | 靠什么 |
|---|---|
| 人物一致 | 共享身份锚点（逐字不变），造型变化写进状态表 |
| 剧情一致 | 连续性状态表 + 每镜"接上一镜"的首尾状态 |
| 画面衔接 | handoff 合同 + 全局保持重申 + 首尾帧链 |

## 提示词是第一交付物

**昨天用户吐槽的核心**：提示词藏在 json 里看不到。

硬约束：
- 每段提示词用 ```` ```text ```` 代码块包住，标"复制这段丢进 [即梦/可灵/Veo]"
- storyboard.json 是备份，不是主交付
- 不许只给 json 让用户自己找

【第 2 段 · 整条 4–9 秒 · 复制这段丢进即梦】

```

【第 3 段 · 整条 9–15 秒 · 复制这段丢进即梦】
```text

## 门禁

技能自己跑 `check-storyboard.py` 验一遍——**不让用户跑命令、不把报错给他看**。必须全绿：

**结构**
- 每镜有 `prompt`（≥ 60 字）、`negative`、`duration`；时长 > 0 且 ≤ `meta.max_shot_duration`（默认 15 秒）
- 时间轴 `start` / `end` 连续，`end - start` 与 `duration` 对得上
- `meta.authorization` 四个字段必填（真人 / 儿童 / 品牌 / 医疗），`pending` 直接拦
- 每镜有 `beat`（这一镜推进了什么剧情）

**首镜 vs 后续镜**
- 首镜：完整写出风格锚 + 身份锚点 + 光线词
- **后续镜：`全局保持：` 行**重申风格锚 + 光线，**`接上一镜：` 行**写上一镜的结束状态

**提示词质量**
- 每镜 prompt 要有镜头词（景别 / 运镜）、光线词、构图词、质感词、约束层
- 不能出现「电影感 / 氛围感 / 高级感」这类模糊词

**台词**
- 有台词：写进 prompt 的「声音」段、写明「正在说话」、标 `character_refs`；不说话标 `silent: true`

**负向词**
- 每镜 `negative` 必须含「二维码 / logo / 水印」三个画面红线

**衔接**
- 非最后镜都有 handoff，`match_on` ≥ 2，`end_state` / `next_start_state` 是可见事实、不含空话
- 角色引用都能在角色卡里找到

**总时长与收尾**
- 总时长与目标偏差 ≤ 1 秒
- 最后一镜有收尾（定格 / 落版 / CTA），`ending.end_state` 是可见画面

## 失败怎么办

- 门禁红了：按报错改字段，改完重跑门禁。
- 画面不对：按 `references/failure-diagnosis.md` 的症状表定位，改成对应的字段，**只重跑出问题那一段**。
- 多段串不起来：先检查后续镜开头有没有"全局保持"和"接上一镜"——没有就补上；有了还不行，就补首尾帧参考。
- 同一问题重试最多 2 次，还不行就换策略（换平台 / 拆镜 / 降级）或停下来把未解决项列给用户，别烧额度。
- 根因在故事就回去改 `story.md`，重跑一百次也没用。
