# 文案转视频工坊（video-studio）

> 输入是**文案**，不是故事。先补故事，再出分镜和提示词，最后才是生成。
> 一条装得下就一条提示词；装不下才拆。拆了就必须接得上。

## 什么时候用

- 用户手里有文案（或刚在本会话里生成过），说「做成视频」「出个分镜」「生成提示词」
- 用户说「多段视频怎么接」「人物别换脸」「前后对不上」
- 用户没给文案，只说「做个面膜视频」——先反问一句是「我按你的意思写一版文案」还是「你贴文案」，二选一，别自己编完再问

## 不做什么

- 不写营销文案本体（交给 `copy-studio`；这里只做简版兜底）
- 不假装出了成片：没有生成能力就交提示词包 + 制作包
- 不引入 `project.json`、审阅看板、五态状态机那种重流程——这里只留一份 `storyboard.json` 做数据源

## 五条铁律

1. **入口是文案。** 先读文案、抽信息点；文案里已有的卖点、价格、承诺一律照搬。
2. **补故事不改事实。** 场景、动作、人物、情绪随便补，补的标 `【补写】`；卖点、价格、功效、CTA 不许动，要动先问。
3. **先算时长再定镜头。** 台词字数 ÷（单次上限 × 4.5）= 需要的条数；装不下就拆，不许硬压。
4. **拆了就写衔接合同。** 每个非最后镜头都要有 handoff，`end_state` 和 `next_start_state` 逐项对齐；禁止写「保持连续」「同上」「延续上一镜」。
5. **收尾要收住。** 最后一镜必须有定格/落版/CTA 中的至少一个，不能话说完画面就断。

## 用这套东西的人，可能什么都不懂

默认用户：不懂开发、不懂 AI、不会装东西、不会跑命令。他不是来学技能的，是来拿结果的。

| 不要 | 要 |
|---|---|
| 说「分镜」「handoff」「提示词工程」「字段」 | 说「画面」「怎么接」「给 AI 的描述」 |
| 让他跑 `python3 ...` / 看报错 / 复制一长串配置 | 技能自己跑、自己验，只把结果给他 |
| 问「用什么模型」「哪个平台」「什么画幅」 | 问「想要真人拍的那种，还是动漫那种？」 |
| 给他一堆文件让他自己找 | 给一张三步就能照做的卡 |
| 一轮问三个问题 | 一轮只让他做一个动作 |

**每轮只让用户做一个动作**：答一句话、点一下、或者复制一次。超过一个他就跑了。

**术语不出门**：内部怎么写都行，跟用户只说人话。

## 问不问：看知不知道

| 情况 | 怎么处理 |
|---|---|
| 已知 / 能推断 | 不问，直接用；推断的打标 |
| 不知道，缺了会返工 | 必须问，问完再动 |
| 不知道，但不影响主线 | 不问，按默认，标出来 |

**必问项**：风格、主体是谁、平台、时长、目标工具。这五个缺一个都会返工。

文案改一版便宜，视频生成一次贵，所以这一段的确认要比文案多——这不是啰嗦，是省钱。

## 委派规则

这套技能是四段流水线（文案 → 故事 → 提示词 → 生成），交接按项目根的 `docs/工作流协议.md` 走。要点：

- **没文案又要做视频**：交给 `copy-video-studio` 出 `script.md`；只有临时需求才用简版兜底，并说明「要更准的文案交给文案技能」。
- **有 `story.md` 就读它**起步，不重问已知；只有文案就自己写完整故事，**不许跳过故事直接拆分镜**。
- **交出去带三样**：交接物、已确认设定、未决项。
- **没有文件能力**：贴完整文本，标「复制走」，不假装落盘。

## 流程：三段，每段有门禁

| 段 | 产物 | 出口门禁 |
|---|---|---|
| ① 文案 → 完整故事 | 故事 `assets/story.md` | 每个信息点都落进故事；补写标了 `【补写】`；卖点/价格/CTA 与原文一致；**用户确认过或标了「我替你定的」** |
| ② 故事 → 分镜 + 提示词 | 分镜表 + `storyboard.json` + 提示词包 | 判过单条还是多条；每镜提示词可复制；角色引用和风格锚写死 |
| ③ 分镜 → 生成或交付 | 成片 / 提示词交接包 / 零工具制作包 | `check-storyboard.py` 全绿；收尾项存在 |

### ① 文案 → 完整故事

按 `references/story-from-copy.md`：拆信息点 → 写完整故事 → 润色 → 确认。

一句话概括：**文案说的是「卖什么」，故事要补的是「谁在什么处境下，为什么信」。**

**故事必须有事件链**——因为 A，所以 B，不是「她洗漱、她涂面霜、她出门」这种并列画面。分镜不连贯，根因常在这。每个事件都问：这件事是上一件导致的吗？

- 故事是**完整叙事**，有开头、转折、结尾，用现在时，能看见画面；长度按内容定，不凑字。
- 一句话故事只是索引，不能拿它去拆分镜。
- 写完要过一遍：用户愿意就逐项确认（人物 / 场景 / 情绪 / 结尾），不愿意就给「我替你定的」清单让他改。
- 故事定稿落 `output/<日期>-<主题>/story.md`，标「已确认」，才进 ②。

### ② 故事 → 分镜与提示词

按 `references/storyboard-and-prompt.md`：

- **先定风格**：真人实拍感 / AI 漫剧 / 3D / 插画图文 / 混合。风格决定整套写法，定错要全部重写；用户没说就给两个选项让他选，这是会返工的项。
- 再算 `镜数 = ceil(口播字数 ÷ (单次上限秒数 × 4.5))`，决定单条还是多条；
- **单条**：出一条完整提示词，按 14 字段骨架写（风格锚 / 主体 / 造型 / 表情 / 动作 / 场景 / 光线 / 镜头 / 构图 / 质感 / 约束 / 负向 / 参数）；
- **多条**：分镜表 + 每镜提示词 + 衔接合同 + 收尾设计；
- **首镜完整，后续接上一镜**：s1 写全主体/场景/风格；s2 之后以「接上一镜：<上一镜结束状态>」开头，主体只写「同一人物」，不再重述外貌——重述就会每镜变脸。
- **每镜写 beat**：这一镜让故事往前走了什么。写不出来，就该删。
- 两条产物都落 `storyboard.json`，供门禁脚本校验。

### ③ 分镜 → 生成或交付

按 `references/production-route.md` 选路线，按 `references/continuity-and-handoff.md` 保一致：

- 宿主有生图/生视频能力 → 先关键帧后视频，逐镜生成，落 `media/`；
- 没有 → 给「提示词交接包」：每镜提示词 + 目标工具 + 生成顺序 + 回填方式；
- 什么都没有 → 零工具制作包：分镜 + 素材清单 + 剪辑步骤 + 提示词。

三种都算完成，别假装出片。

**声音单独交付**：视频模型大多不出台词，所以【台词 / 配音】必须单独给一份，给 TTS 或真人录音用。没给台词 = 视频是哑的 = 白做。

## 一致性三件套

| 要保的 | 靠什么 |
|---|---|
| 人物一致 | 角色卡：身份锚点锁死长相，阶段造型单独管，每镜提示词引用同一段 |
| 剧情一致 | 连续性状态表：每镜记录「在哪 / 穿什么 / 拿什么 / 情绪 / 时间光线」，写下一镜先查表 |
| 画面衔接 | handoff 合同 + 首尾帧链 + 轴线不跳 + 节奏表对齐 |

细节见 `references/continuity-and-handoff.md`。

## 提示词是交付物，不是内部数据

用户最终要靠提示词去生成。所以：

- **单条**：一段完整提示词，代码块包住，标「复制这段」。
- **多条**：逐段编号，每段一个代码块，按顺序给——用户要一段一段生成。
- **操作卡里**：提示词嵌在「第 2 步」，直接可复制。
- **不许**只给摘要、不许说「完整版在 storyboard.json 里」、不许让用户自己拼。

用户越不懂 AI，越要给全——他得把这段粘到豆包 / 即梦里去，缺一个字都白搭。

**细到能直接粘**：不加工、不补充、不「你按这个再改改」，粘进去就该出片。14 字段每项都写到下限（见 `storyboard-and-prompt.md` §2）。

## 输出格式

```text
> 假设：<平台> / <时长> / <类型> / <目标> / <风格>
> 模式：单条提示词 / N 段分镜

【完整故事】
<完整叙事 + 分场 + 我替你定的 + 补写清单 + 确认状态>

【分镜 + 提示词】
<分镜表>
<逐段提示词：每段一个代码块，标「第 N 段，复制这段」>

【衔接合同】
<多条时才有：每段的 end_state / next_start_state>

【台词 / 配音】
<逐句台词 + 配音方式，能直接粘 TTS；没有台词的镜头说明是空镜>

【怎么做】
<三选一：
 - 我能直接出视频 → 给视频 + 一句「看看行不行」
 - 用户自己生成 → 操作卡：打开哪个 App、粘哪段、发回什么
 - 都没有 → 拍摄清单：拍什么、怎么拍、拍完发我>
```

## 门禁

技能自己跑 `check-storyboard.py` 验一遍——**不让用户跑命令、不把报错给他看**。必须全绿：

- 每镜有正向提示词、负向词、时长
- 非最后镜都有 handoff，且首尾状态不含空话
- 角色引用都能在角色卡里找到
- 总时长与目标时长偏差 ≤ 1 秒
- 最后一镜有收尾（定格 / 落版 / CTA）

## 失败怎么办

- 门禁红了：按报错改字段，改完重跑门禁。
- 画面不对：按 `references/failure-diagnosis.md` 的症状表定位，改成对应的字段，**只重跑出问题那一段**。
- 同一问题重试最多 2 次，还不行就换策略（换平台 / 拆镜 / 降级）或停下来把未解决项列给用户，别烧额度。
- 根因在故事就回去改 `story.md`，重跑一百次也没用。
