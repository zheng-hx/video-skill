# 技能总览与职责边界

> 一个入口，四个技能。边界写死，避免互相抢触发。

## 结构

```text
video-design-skills（入口）
├── copy-video-studio    文案
├── video-studio         视频
├── live-media-ops       招募
└── live-media-router    路由
```

入口只负责安装、注册、诊断，不碰具体产出。

## 职责表

| 能力 | 归属 | 说明 |
|---|---|---|
| 招募文案（招主播 / 招人） | `copy-video-studio` | 类型选「招募」，结构走待遇→条件→机会→怎么来 |
| 带货 / 种草 / 人设 / 品牌 / 活动 / 剧情文案 | `copy-video-studio` | 类型表见它的 `references/copywriting.md` §1.1 |
| 秀场直播话术 | `copy-video-studio` | 走 `references/live-show.md` |
| 文案 → 故事 → 分镜 → 逐镜提示词 | `video-studio` | 走 `references/story-from-copy.md` + `storyboard-and-prompt.md` |
| 多段衔接 / 人物一致 / 收尾设计 | `video-studio` | 走 `references/continuity-and-handoff.md` |
| 生成路线 / 零工具制作包 | `video-studio` | 走 `references/production-route.md` |
| 主播招募 JD | `live-media-ops` | 走 `assets/host-jd-template.md` |
| 候选人筛选 / 面试打分 | `live-media-ops` | 走 `references/host-recruit.md` |
| 「我这账号该怎么弄」「该找哪个技能」 | `live-media-router` | 只分流，不出稿 |

## 为什么这样切

- **文案和视频拆开**：视频有独立的提示词工程、连续性、衔接问题，塞进文案技能会把两边都写浅。拆开后靠中间产物连接，不靠对话记忆。
- **中间产物是约定**：`copy-video-studio` 落 `script.md`，`video-studio` 读它出 `story.md` 和 `storyboard.json`。落盘位置统一在 `output/<日期>-<主题>/`；存不了文件才退回会话内交付。
- **招募是另一条线**：JD、筛选、面试是流程活，不走内容创作。所以独立。
- **路由只做路标**：它知道的比它做的多。一旦开始出稿，就会和下面几个抢。

## 串联怎么走

```text
用户说「写条文案，再做成视频」
  → copy-video-studio 出文案，落 script.md
  → video-studio 读 script.md：补故事 → 分镜 → 提示词 → 生成或交接
```

交接靠固定字段：`script.md`、`storyboard.json`、`handoff`。不靠「上次说的那个」。

## 三段流水线（video-studio 内部）

> 跨技能的交接规则见 [工作流协议](./工作流协议.md)。

| 段 | 产物 | 出口门禁 |
|---|---|---|
| ① 文案 → 完整故事 | 故事（落 `story.md`） | 信息点全落、补写标了 `【补写】`、卖点不变、已确认 |
| ② 故事 → 分镜 + 提示词 | 分镜表 + `storyboard.json` | 判过单条/多条、每镜提示词可复制 |
| ③ 分镜 → 生成或交付 | 成片 / 交接包 / 制作包 | `check-storyboard.py` 全绿 |
