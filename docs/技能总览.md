# 技能总览与职责边界

> 一个入口，两个技能。边界写死，避免互相抢触发。
> v2.0 从四个技能收缩为两个：文案能力 + 视频能力。招主播、主播日常、行业观察等所有对外内容场景，统一归文案能力和视频能力。路由逻辑内置在入口。

## 结构

```text
video-design-skills（入口）
├── copy-video-studio    文案
└── video-studio         视频
```

入口只负责安装、注册、诊断和一句话分流，不碰具体产出。

## 职责表

| 能力 | 归属 | 说明 |
|---|---|---|
| 任何场景的对外内容文案（招主播 / 主播日常 / 行业观察 / 成功案例 / 品牌展示） | `copy-video-studio` | 默认走故事骨架，让观众觉得公司懂行、真诚、靠谱，主动来联系 |
| 带货 / 种草 / 品牌（偏广告类） | `copy-video-studio` | 切广告骨架（钩子→痛点→卖点→信任→CTA） |
| 文案 → 故事（展开或从零补写）→ 分镜 → 逐镜提示词 | `video-studio` | 文案是故事型走展开模式；广告型走从零补写模式 |
| 多段衔接 / 人物一致 / 收尾设计 | `video-studio` | 全局保持 + 接上一镜 + handoff 合同 |
| 生成路线 / 零工具制作包 | `video-studio` | 有工具出片，没工具给制作包 |
| JD 模板 / 面试评分表 | `copy-video-studio/assets/host-jd-template.md` | 独立工具，人工复制使用 |

## 为什么这样切

- **文案和视频拆开**：视频有独立的提示词工程、连续性、衔接问题，塞进文案技能会把两边都写浅。拆开后靠中间产物连接，不靠对话记忆。
- **中间产物是约定**：`copy-video-studio` 落 `script.md`，`video-studio` 读它出 `story.md` 和 `storyboard.json`。落盘位置统一在 `output/<日期>-<主题>/`；存不了文件才退回会话内交付。
- **招主播不是一个技能，是文案/视频的场景之一**：所有对外内容统一走故事骨架，不管你说的是招主播、主播日常还是行业观察。统一的目标是让观众觉得公司懂行、真诚、靠谱，主动联系。
- **后端工具不独立成技能**：JD/面试/筛选是执行工具，不是内容生产能力。放在顶层 scripts/ 目录下当模板，人工复制使用。

## 串联怎么走

```text
用户说「写条文案，再做成视频」
  → copy-video-studio 出文案，落 script.md（故事骨架 + 限流词黑名单）
  → video-studio 读 script.md：判断故事型走展开 → 完整故事 → 分镜 → 逐镜提示词（全局保持 + 接上一镜）→ 生成或交接
```

交接靠固定字段：`script.md`、`story.md`、`storyboard.json`。不靠「上次说的那个」。

## 三段流水线（video-studio 内部）

> 跨技能的交接规则见 [工作流协议](./工作流协议.md)。

| 段 | 产物 | 出口门禁 |
|---|---|---|
| ① 文案 → 完整故事 | 故事（落 `story.md`） | 判断对了模式（故事型=展开/广告型=从零补写）；信息点全落、补写标了 `【补写】`、卖点不变、已确认 |
| ② 故事 → 分镜 + 提示词 | 分镜表 + `storyboard.json` | 判过单条/多条；首镜共享字段完整；后续镜有"全局保持"和"接上一镜"；每镜有声音三件套；`meta.review` 两个审核位已置 true；每镜提示词可复制 |
| ③ 分镜 → 生成或交付 | 成片 / 交接包 / 制作包 | `check-storyboard.py` 全绿；提示词是第一交付物（代码块包出来）；收尾存在 |
