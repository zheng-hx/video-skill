# 怎么测试技能包

> 技能包不是代码，没有单测。它是给模型读的文档，所以「测试」只能分层做：从「文件长得对不对」一路测到「模型照着做会不会做对」。

## 五层

| 层 | 测什么 | 怎么测 | 现状 |
|---|---|---|---|
| L1 静态 | 结构、引用、描述长度、触发词 | `validate-package.py` / `check-evals.py` / `check-triggers.py` | ✅ 有 |
| L2 门禁 | 产物结构：字段、时长、衔接、收尾 | `check-storyboard.py` | ✅ 有 |
| L3 基线 | 「合格产物」长什么样 | 手做参考产物 → `run-evals.py` | ✅ 10 条 |
| L4 真跑 | 模型读了技能能不能做对 | 独立 agent 读技能 → 执行 → 判定 | ⚠️ 手动跑过，`evals/runs/live-test-*` 被 gitignore，产物不入库 |
| L5 端到端 | 真实用户 + 真实平台 | 真发一条视频出去看效果 | ❌ 没做 |

## 每层测不出什么

- **L1 测不出**：模型读了会不会照做。文件全绿，模型也可能跳过流程。
- **L2 测不出**：画面好不好。结构合格的分镜可能很平。
- **L3 测不出**：模型能不能产出合格产物。参考基线是人做的，不代表模型能做到。
- **L4 测不出**：真实平台效果。同样的提示词，不同模型出片差很远。
- **L5 才能测全部**，但贵、慢、不可重复。

## L4 怎么做

1. 起一个**干净 agent**，只给：技能路径 + 一句用户输入。
2. 不让它读已有产物（防止抄）。
3. 它自己跑完整流程，产出落 `evals/runs/<测试名>/`。
4. 跑 `run-evals.py --eval ... --run-dir ...` 判定。
5. 看结果决定改技能还是改评测。

## 一个反直觉的点

评测要能区分「技能起作用了」和「模型本来就会」。

做法：**同一输入跑两次，一次给技能，一次不给**，对比产出。

- 两次都合格 → 评测太简单，测不出技能价值。
- 给技能才合格 → 技能有效。
- 给了还不合格 → 技能写得不清楚，或者门禁没覆盖到。

## 现在最该补的

1. **L4 跑 2–3 条**，看模型真读技能会做成什么样。
2. **L5 跑 1 条**，拿真实产品，生成一条真的视频，看像不像。
3. 按结果改技能，而不是继续加文档。
