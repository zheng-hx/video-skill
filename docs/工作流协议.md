# 技能间工作流协议

> 「交给 X」不是一句话，是一套可检查的交接。
> 这份协议规定四件事：谁在什么阶段负责、交什么、什么时候必须交、交完怎么验。

## 1. 三段流水线

| # | 段 | 负责技能 | 输入 | 输出（交接物） | 出口门禁 |
|---|---|---|---|---|---|
| 1 | 文案 | `copy-video-studio` | 需求 / 产品 | `script.md` | 假设行 + 正文 + 限流词处理 + 合规标注 |
| 2 | 故事 | `video-studio` | `script.md` | `story.md` | 模式选对了（故事型=展开/广告型=从零补写）+ 信息点全落 + 补写标注 + 用户确认 |
| 3 | 提示词 | `video-studio` | `story.md` | `storyboard.json` + 提示词包 | `check-storyboard.py` 全绿（首镜共享字段完整 + 后续镜全局保持/接上一镜） |
| 4 | 生成 | `video-studio` / 用户 | `storyboard.json` | 成片 / 交接包 / 制作包 | 交付边界说清楚 |

## 2. 什么时候必须委派

**必须交出去**（三条任一）：

1. 下游有独立技能，而当前技能只有「简版兜底」——简版写浅了会拉低整条质量。
2. 需要落交接物（`script.md` / `story.md` / `storyboard.json`），而当前阶段还没落。
3. 用户要求跨会话继续——没有交接物就断。

**可以不交**（两条任一）：

1. 下游内容已经完整在上下文里，当前技能能原样执行。
2. 用户明说「就在这儿做完，别换技能」。

## 3. 委派时带三样

| 带什么 | 说明 |
|---|---|
| 交接物 | 文件路径，或完整文本 |
| 已确认设定 | 平台 / 时长 / 风格 / 目标 / 目标工具 |
| 未决项 | 用户还没定的，列清楚，别让下游再猜 |

**不许带的**：半成品、猜测、「大概是这样」。

## 4. 交出去之前自检

- [ ] 交接物存在（文件）或完整贴出（文本）
- [ ] 交接物里有下一段必需的字段
- [ ] 已确认设定写全了
- [ ] 用户知道换了技能、换到哪个

## 5. 接过去之后规矩

- [ ] 先读交接物，**不重问已知**
- [ ] 缺字段就问，不猜
- [ ] 发现冲突直接指出，不硬做
- [ ] 做完回写自己的交接物，让下一段能接

## 6. 没有文件能力时

按文本交接：把 `script.md` / `story.md` / `storyboard.json` 的完整内容贴进对话，标「复制走」。

**不假装落盘**，也不反复尝试写文件然后报错——试一次失败就切文本。

## 7. 阶段间要不要用户确认

| 转场 | 要不要确认 | 理由 |
|---|---|---|
| 需求 → 文案 | 不确认，直接出 | 文案改一版便宜 |
| 文案 → 故事 | 不确认，直接出完整故事 | 故事改起来也便宜 |
| 故事 → 提示词 | **必须确认** | 分镜错了整条重做 |
| 提示词 → 生成 | **必须确认** | 生成一次要钱要时间 |

## 8. 失败怎么退

| 哪一段不对 | 退到哪 | 重做什么 |
|---|---|---|
| 故事不对 | 故事 | 改 `story.md`，重拆分场 |
| 分镜不对 | 提示词 | 改 `storyboard.json`，不重写故事 |
| 多段串不起来 | 提示词 | 检查后续镜有没有"全局保持"和"接上一镜"——没有就补；有了还不行，就补首尾帧参考 |
| 生成效果不对 | 看现象 | 脸漂 → 补角色卡；接不上 → 改 handoff；动作糊 → 改动作描述或拆镜 |

退回后按 `skills/video-studio/references/failure-diagnosis.md` 的现象表定位根因，**改完再跑**，不裸重试。

退的时候只退到出问题的那一段，不要从头重来。
