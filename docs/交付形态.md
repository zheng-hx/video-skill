# 交付给「只想用」的人

> 这套技能包是**零件**，不是成品。给不懂技术的人用，得先有个壳。
> 下面三种形态，按「谁维护」选。

## 先认清一件事

| 现在有 | 他需要 |
|---|---|
| 2 个 markdown 技能 | 一个能打开的入口 |
| `check-storyboard.py` 门禁 | 看不见的后台 |
| 提示词包 / 分镜表 | 「复制这段 → 点生成」 |
| 装技能、配环境 | 你替他装好，或者点个链接 |

**他只在最后一步出现**：说一句话、点一下、发回一个文件。前面全部由系统做完。

## 形态 A：装进现成的 AI 助手（最快）

**谁做**：你，做一次。
**他做**：打开对话，说一句话。

```text
1. 选一个他已经在用的 AI 助手（豆包 / 扣子 / 微信机器人 / 你装的宿主）
2. 把 skills/video-design-skills/capabilities 下的 copy-video-studio 和 video-studio 装进去
3. 给他一个固定入口：桌面图标 / 群聊 / 收藏的对话
4. 教他一句话：「给我做个面膜视频」
```

优点：一天能配上，零开发。
限制：他得知道去哪打开；助手得支持装技能（不支持就把 SKILL.md 内容当系统提示词贴进去）。

## 形态 B：做成网页 / 小程序

**谁做**：开发。
**他做**：点链接，打字。

- 前端只有一个输入框 + 结果区，不要设置项。
- 后端接模型，把技能内容当系统提示词。
- 生成、校验、重跑都在后台，不暴露给用户。

优点：体验最好，谁都能用。
限制：要开发、要服务器、要账号。

## 形态 C：微信群 / 企微机器人

**谁做**：开发。
**他做**：在群里发一句。

- 接机器人，绑技能，群里发指令就出结果。
- 唯一门槛是微信风控，需要企业主体。

优点：他不用装任何东西。
限制：要开发，且要合规。

## 怎么选

1. **先试 A**：找个人半天配上，拉一个真实用户用一周。
2. 用的人超过 3 个，或者他开始抱怨「还要复制粘贴」→ 做 B。
3. 团队/公司场景、要群发 → 做 C。

## 不管哪种形态，都必须做到

- 每轮只让他做一个动作。
- 不说术语。
- 出错不说「报错」，说「这段没成，我换个说法再试一次」。
- 能自己修的自己修，修不好才找他，而且只问一个问题。
